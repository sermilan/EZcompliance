# 场景：安全事件应急处置

> **来源**: [[小型个人信息处理者个人信息保护简化措施规定]]（第十六、十五条）
> **涉及 COU 数量**: 3
> **适用主体**: 小型个人信息处理者、公安机关、履行个人信息保护职责的部门

## 场景概述

本场景覆盖个人信息泄露、篡改、丢失事件发生或可能发生时的应急义务。第十六条规定三段式处置链：**立即补救 → 通知个人与监管部门 → 涉嫌犯罪报案**。简化点仅体现在通知方式上（客观条件受限时可用张贴公告、弹窗、网站公告），处置义务本身不简化。第十五条的应急预案建设义务已通过组织管理文件方式极简化（参见[[场景-合规审计影响评估与内部制度]]）。

## 关联 COU

### 应急处置 (第十六条)

- [[COU-R-SPP-十六-应当-立即补救并通知]] — 立即采取补救措施，依法通知个人，按规定通知履职部门 (w=12.0)
- [[COU-R-SPP-十六-可以-简便方式通知个人]] — 客观条件限制无法其他方式通知时可仅用张贴公告/弹窗/网站公告 (w=8.0)
- [[COU-R-SPP-十六-应当-涉嫌犯罪报案]] — 涉嫌犯罪的应当及时向公安机关报案 (w=12.0)

### 预案建设（跨场景引用，第十五条）

- [[COU-R-SPP-十五-可以-简便方式建制度预案]] — 在组织管理文件中明确应急处置要求即建立应急预案 (w=8.0)

## 合规要点

1. **"发生或可能发生"即触发**：威胁未实际造成泄露但存在现实可能时，补救与通知义务已经启动，与个保法口径一致。
2. **补救优先于通知**：条文顺序为"立即补救→通知"，先止血后通报，避免通知期间损害扩大。
3. **简便通知是兜底而非首选**：仅在"确因客观条件限制无法通过其他方式通知个人"时才可仅用公告方式，能直接触达（短信、电话、APP推送）的仍应直接触达。
4. **报案义务独立存在**：涉嫌犯罪（如窃取数据、内鬼泄露）时向公安报案与通知个人、通知履职部门并行，互不替代。
5. **裁量从宽挂钩应急表现**：事件后及时通知个人、采取补救并主动通知有关部门的，构成第十九条第（三）项从轻减轻处罚事由——应急处置质量直接影响处罚结果（参见[[场景-处罚裁量与监管支持]]）。
