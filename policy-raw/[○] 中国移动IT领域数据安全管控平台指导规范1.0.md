# 前 言

本标准规定了中国移动业务支撑网数据安全管控平台的总体建设要求、平台框架、主要功能定义、关键技术实施和实现方法等内容。本标准基于中国移动数据安全管理的现状，结合上级机构对数据安全管理工作的具体要求进行制定，指导中国移动IT领域各单位数据安全管控平台建设工作。

本标准由中国移动通信集团信息技术中心提出并归口。

本标准起草单位：中国移动通信集团信息技术中心

本标准主要起草人：

本标准解释单位：中国移动通信集团信息技术中心

# 范围

为加强IT领域全网数据安全管理能力，贯彻和落实上级监管机的相关数据安全管理要求，制定本标准供中国移动内部在IT领域数据安全管控平台建设过程中进行技术指导。

本标准规定了中国移动业务支撑网数据安全管控平台总体建设要求、平台框架、主要功能定义、关键技术实施和实现方法等内容。

# 总体说明

## 建设目标

数据安全管控平台是承载中国移动IT领域全网及各省数据安全管理和技术手段的集中化支撑平台，通过数据安全运营能力、数据安全管控能力、数据安全监控能力的建设，实现IT领域数据安全统一运营、集中管控，提升数据安全技术支撑保障能力。

所有涉敏系统均要接入数据安全管控平台。全网中心和各省公司依据《中国移动客户信息安全保护管理规定》、《中移信息技术有限公司数据安全管理办法》确定辖内业务系统的涉敏性质。

## 功能架构

![C:\Users\zjf\Desktop\图片2.png](data:image/png;base64...)

图 4‑2数据安全管控平台功能架构图

数据安全管控平台分为数据安全运营能力、数据安全管控能力和数据安全监控能力。

**【数据安全运营能力】：**通过实现数据资源安全运营、数据安全策略运营、数据安全事件运营、数据安全风险运营等能力的建设，为数据安全提供信息化支撑手段。

**【数据安全管控能力】：**通过实现数据发现、策略管控、事件监测、风险分析等能力的建设，形成数据安全闭环管理。

**【数据安全监控能力】：**通过落实集中监控能力和业务侧基础防护要求等能力，并对接现有平台数据安全管控能力，形成数据安全的整体监控和防护能力。

### 演进路线图

**后续计划：**全网中心完成数据安全管控平台全网覆盖，省公司完成优化接入全网平台。

# 全网中心系统功能

## 数据安全运营能力

### 数据资源安全运营

#### 数据资源地图

【功能定义】

数据资源地图能够对数据资源的分布情况进行综合呈现。应包括：资源接入覆盖范围呈现、数据资源清单呈现、敏感数据分布呈现。

【功能要求】

* 资源接入覆盖范围呈现：支持以地图形式呈现数据资源的接入覆盖范围，展现内容至少应包括：资源池、业务系统、资源IP；支持按敏感数据分类、敏感数据分级、敏感数据特征等属性进行筛选；
* 数据资源清单呈现：支持以列表形式呈现数据资源清单，展现内容至少应包括：业务系统、资源IP、敏感数据分级、敏感数据分级、是否执行扫描；
* 敏感数据分布呈现，能够以拓扑图形式呈现敏感数据的分布情况，展现内容包括：

|  |  |  |
| --- | --- | --- |
| **编号** | **名称** | **说明** |
| 1 | 业务系统名称 | 所属业务系统名称 |
| 2 | 数据资源服务器IP | 敏感数据所在服务器IP |
| 3 | 敏感数据分级 | 敏感数据对应的分级 |
| 4 | 敏感数据分类 | 敏感数据对应的分类 |
| 5 | 敏感数据特征 | 敏感数据对应的特征 |
| 6 | 数据资源类型 | 数据资源类型，如：数据库 |
| 7 | 敏感数据存储路径 | 敏感数据的存储位置 |

#### 数据资源稽核

【功能定义】

通过数据资源稽核对全网数据资源发现工作进行推进和监督。应包括：数据资源扫描情况稽核、数据资源认领情况稽核。

【功能要求】

* 数据资源扫描情况稽核：支持以数据资源清单为依据，对数据资源表、文件级粒度的扫描情况进行稽核，能够以图表形式呈现数据资源的整体扫描率；支持针对各业务系统数据资源扫描情况进行排名，展现内容应包括：业务系统名称、数据资源扫描率、排名；支持以列表形式呈现数据资源扫描稽核的详细信息，展现内容至少应包括：

|  |  |  |
| --- | --- | --- |
| **编号** | **名称** | **说明** |
| 1 | 业务系统名称 | 所属业务系统名称 |
| 2 | 数据资源服务器IP | 敏感数据所在服务器IP |
| 3 | 数据源信息 | 数据库实例或文件存储路径 |
| 4 | 表/文件名 | 数据库表或者文件名 |
| 5 | 责任人 | 责任人落实到表/文件，如表/文件的责任人为多个，可列多个 |

* 数据资源清单检索：数据资源清单查询提供多种条件组合查询，查询条件至少应包含：服务器IP、资源类型、是否涉敏、所属部门、所属业务系统、责任人、对应数据、敏感数据类别、敏感数据级别等；支持数据资源列表展示，展示内容应包含：服务器IP、资源类型、是否涉敏、所属部门、所属业务系统、责任人；支持按照所属部门或业务系统进行展示；支持涉敏数据资源详情展示，展示内容应包含：存储位置、字段、对应数据、敏感数据类别、敏感级别；支持对查询筛选后的数据资源清单进行导出，导出格式至少包含Excel；

### 策略管控

#### 分类分级策略

【功能定义】

为落实数据安全规范标准，需要制定分类分级策略。分类分级策略包括策略的管理、下发和对应。

【功能要求】

* 策略管理：包括策略的创建、变更、注销归档、查询,所有操作应记录明细日志。支持通过人工录入或文件导入的方式创建策略。支持对已录入的策略进行变更，但已注销归档的策略不可变更。在注销时需要填写注销原因，策略归档后至少在线保存1年，以便进行安全审计。支持根据敏感等级、数据类型查询策略。分级分类策略内容应至少包括：

|  |  |  |
| --- | --- | --- |
| **编号** | **名称** | **说明** |
| 1 | 敏感等级 | 包括等级名称和等级高低顺序值 |
| 2 | 各等级下包含的数据类型 | 每个等级可能包括多个数据类型 |

* 策略下发：策略在创建、变更、注销后，需要被下发到指定的责任人（各部门/省中心安全管理员）。一个策略会有多个策略责任人。策略责任人在收到策略后，需要将策略分解成敏感数据扫描组件可使用的规则，并在组件上执行相应处理（录入、变更、删除）。可通过邮件、工单或平台内部通知等方式下发分类分级策略，每次下发时为全量下发。下发过程应记录明细日志。
* 策略对应：应支持为策略标注对应的规范标准，以及对应能力组件上实际录入的规则，以便后期对数据安全策略进行稽核。

### 业务侧基础防护要求

IT各部门/各省中心涉及到数据资产采集、存储、传输、使用、交换的业务系统，参照本规范业务侧基础防护要求进行水印、脱敏、加密和模糊化等业务侧防护能力的改造、建设工作，同时参照本规范业务侧基础防护接口标准，提供数据安全管控平台能力的接入。。

#### 数据水印

【功能定义】

各业务系统应落实涉敏数据的数据水印能力，并提供数据水印日志输出、数据水印规则输出。数据水印包括网页水印、文件水印功能

【功能要求】

* 网页水印：根据数据分类分级、涉敏数据定义，落实对网页的数据水印能力。水印算法根据实际业务需求进行选择；
* 文件水印：根据数据分类分级、涉敏数据定义，落实对文件的数据水印能力。水印算法根据实际业务需求进行选择。

#### 数据加密

【功能定义】

各业务系统应落实涉敏数据的数据加密能力，并提供数据加密日志输出、数据加密规则输出。数据加密包括存储数据加密、传输数据加密功能。

【功能要求】

* 存储数据加密：根据数据分类分级、涉敏数据定义，落实对存储在文件服务器、数据库服务器、大数据、云平台等业务上的数据加密能力。加密算法根据实际业务需求进行选择。
* 传输数据加密：根据数据分类分级、涉敏数据定义，落实传输数据的加密保护能力。加密算法根据实际业务需求进行选择。

#### 数据脱敏

【功能定义】

各业务系统应落实涉敏数据的数据脱敏能力，并提供数据脱敏日志和数据脱敏规则输出的能力。数据脱敏包括动态脱敏和静态脱敏。

【功能要求】

* 静态脱敏：根据数据分类分级、涉敏数据定义，落实敏感数据存储或迁移时的数据脱敏能力。应支持多种脱敏算法和关系型数据库、非关系型数据库、文件等类型的脱敏，支持为不同的业务场景设置不同的脱敏算法，支持单次和周期运行。
* 动态脱敏：根据数据分类分级、涉敏数据定义，落实敏感数据使用时的数据脱敏能力。应支持多种脱敏算法和关系型数据库、非关系型数据库、文件等类型的脱敏，支持不同用户访问同一数据时使用不同的脱敏算法。

#### 客户信息模糊化

【功能定义】

为确保客户信息安全性，不被非正常业务需求访问，不被无限制传播、扩散，各业务系统应落实客户信息模糊化处理能力，全网中心系统在建设过程中应覆盖已有的省级系统的客户信息模糊化处理能力，其他业务系统应参考《客户界面信息模糊化业务规范》进行实际的能力落地，并提供客户信息模糊化日志输出、客户信息模糊化规则输出的能力。

【功能要求】

详细要求参见《客户界面信息模糊化业务规范》

|  |  |  |

### 策略管控

#### 分类分级策略

【功能定义】

为落实数据安全规范标准，需要制定分类分级策略。分类分级策略包括策略的管理、下发和对应。

【功能要求】

* 策略管理：包括策略的创建、变更、注销归档、查询,所有操作应记录明细日志。支持通过人工录入或文件导入的方式创建策略。支持对已录入的策略进行变更，但已注销归档的策略不可变更。在注销时需要填写注销原因，策略归档后至少在线保存1年，以便进行安全审计。支持根据敏感等级、数据类型查询策略。分级分类策略内容应至少包括：

|  |  |  |
| --- | --- | --- |
| **编号** | **名称** | **说明** |
| 1 | 敏感等级 | 包括等级名称和等级高低顺序值 |
| 2 | 各等级下包含的数据类型 | 每个等级可能包括多个数据类型 |

* 策略下发：策略在创建、变更、注销后，需要被下发到指定的责任人（各部门/省中心安全管理员）。一个策略会有多个策略责任人。策略责任人在收到策略后，需要将策略分解成敏感数据扫描组件可使用的规则，并在组件上执行相应处理（录入、变更、删除）。可通过邮件、工单或平台内部通知等方式下发分类分级策略，每次下发时为全量下发。下发过程应记录明细日志。
* 策略对应：应支持为策略标注对应的规范标准，以及对应能力组件上实际录入的规则，以便后期对数据安全策略进行稽核。

#### 数据资源发现策略

【功能定义】

为确保数据安全规范标准的落实，需要制定数据资源发现策略,为数据资源发现组件指定在目标服务器上发现可能存在的数据库的方法。包括策略的管理、下发和对应。

【功能要求】

* 策略对应：应支持为策略标注对应的规范标准，以及对应能力组件上实际录入的规则，以便后期对数据安全策略进行稽核。

【功能定义】

各业务系统应落实涉敏数据的数据水印能力，并提供数据水印日志输出、数据水印规则输出。数据水印包括网页水印、文件水印功能

【功能要求】

* 网页水印：根据数据分类分级、涉敏数据定义，落实对网页的数据水印能力。水印算法根据实际业务需求进行选择；
* 文件水印：根据数据分类分级、涉敏数据定义，落实对文件的数据水印能力。水印算法根据实际业务需求进行选择。
  + - 1. **数据加密**

【功能定义】

各业务系统应落实涉敏数据的数据加密能力，并提供数据加密日志输出、数据加密规则输出。数据加密包括存储数据加密、传输数据加密功能。

【功能要求】

* 存储数据加密：根据数据分类分级、涉敏数据定义，落实对存储在文件服务器、数据库服务器、大数据、云平台等业务上的数据加密能力。加密算法根据实际业务需求进行选择。
* 传输数据加密：根据数据分类分级、涉敏数据定义，落实传输数据的加密保护能力。加密算法根据实际业务需求进行选择。
  + - 1. **数据脱敏**

【功能定义】

各业务系统应落实涉敏数据的数据脱敏能力，并提供数据脱敏日志和数据脱敏规则输出的能力。数据脱敏包括动态脱敏和静态脱敏。

【功能要求】

* 静态脱敏：根据数据分类分级、涉敏数据定义，落实敏感数据存储或迁移时的数据脱敏能力。应支持多种脱敏算法和关系型数据库、非关系型数据库、文件等类型的脱敏，支持为不同的业务场景设置不同的脱敏算法，支持单次和周期运行。
* 动态脱敏：根据数据分类分级、涉敏数据定义，落实敏感数据使用时的数据脱敏能力。应支持多种脱敏算法和关系型数据库、非关系型数据库、文件等类型的脱敏，支持不同用户访问同一数据时使用不同的脱敏算法。

## 平台账号及权限管理

【功能定义】

省公司系统具备账号及权限管理能力，省公司系统平台管理及安全事件管理、安全运营管理、安全监控管理，具备添加账号、分配权限功能权限最小原则：对纳入管控的所有资源进行集中的授权管理，践行最小权限原则、责任分离原则和数据抽象原则。通过建立基于角色的授权模型帮助管理员实现对各类人员的权限最小化、集中授权与分级分类管理。

系统角色分三级，分为：省公司安全管理员、省公司安全运营员、省中心/各部门安全管理者、省中心/各部门安全运营者、省中心业务系统管理者、、各省中心/各业务部门数据资源主管责任人。

【功能要求】

* 账号管理包括：添加账号、删除账号、修改账号信息。
* 权限管理包括：新建权限、删除权限、分配权限。
* 省公司安全管理员：具备省公司平台除涉敏数据外的所有功能查看权限。
* 省公司安全运营员：具备省公司平台全部功能的管理权限，对敏感数据的操作触发金库模式，由省公司安全管理员审批后才能进行操作。
* 省中心/各部门安全管理者：具备省公司平台除涉敏数据外的所有查看功能，但只能限于查看本省/本部门数据。
* 省中心/各部门安全运营者：具备本省/本部门数据安全管控平台的全部功能的管理权限，对敏感数据的操作触发金库模式，由本省/本部门安全管理者审批后才能进行操作

# 非功能性要求

为了保证系统安全运行，防止系统受到外来攻击、破坏和非法访问，全网数据安全管控平台和省公司数据安全管控平台均需从不同层次并利用多种手段来保证系统的安全。主要包括系统的主机安全、网络安全、应用安全、数据安全、金库模式、4A管控、数据水印、数据脱敏、数据加密以及安全技术保障等功能。

* 主机安全

1.需要关闭掉文件共享服务，安装防病毒软件，开启防火墙，有需要可纳入域控系统、设定主机端口访问白名单、启用实时防护与接受管理，进行周期性对系统全机病毒扫描。

2.关闭不必要的端口，及时进行补丁的升级和安全配置，并配合进行入侵检测和漏洞扫描等安全检查工作。

* 网络安全

1.网络接入控制：未经批准严禁通过电话线、各类专线接到外网；如确有需求，必须申请备案后先进行与内网完全隔离，才可以实施。

2.网络安全域隔离：如果有需要与公司外部通讯的服务器，应在保证自身安全的情况下放入公司防火墙DMZ区，该应用服务器与公司内部系统通讯时，应采用内部读取数据的方式。其他类应用系统服务器放置在公司内部网中。

* 应用安全

1.应保证自身的应用安全要求，包括不限于：密码的存储与传输禁止使用明文；禁止在COOKIE中保存用户密码；防止跨站请求伪造；进行异常输入验证等安全防护能力，防止网页篡改等要求。

2.同其他系统间互通在性能允许情况下支持安全的加密通讯连接。

3.能够记录系统运行过程中产生的登录日志、操作日志、管理配置日志和系统自身告警日志等；

* 数据安全

1.数据传输的机密性：重点应用系统中传输关键、敏感数据时要采用传输加密技术，实现数据机密性要求；密码算法必须具有较高的保密强度和抗攻击能力；

2.数据生成、存储、使用必须是符合中国移动相关的安全规范，有明确的数据安全访问、存储、备份机制；

* 金库模式

1.系统资源金库要求：当涉及系统资源的敏感数据访问时，必须触发金库授权审批，可以选择现场授权、远程授权或自动授权任意一种或多种；授权条件可以选择单次授权或按时间段授权；

2.当涉及应用资源的敏感数据访问时，必须触发金库授权审批，可以选择现场授权、远程授权或自动授权任意一种或多种；授权条件可以选择单次授权或按时间段授权，针对敏感数据导出类操作原则只允许单次授权；当点击当点击含有敏感信息的菜单或按钮被点击时，触发金库授权审批。

* 4A管控

1.数据安全管控平台的帐号口令纳入4A系统进行统一管理和审计，系统帐号口令的设置应满足4A技术规范的要求，并采用多因子账号认证控制。

2.数据安全管控平台日志应当按照5w1h（4w:时间、地点、人物、对象、凭据 1h:动作）的原则进行记录，并对关键操作进行内容级的记录，相关日志应发送4A审计统一管理。

* 数据水印

数据安全管控平台敏感数据外发需进行水印标识，水印记录内容包括：访问的时间节点、ip地址、身份等。

* 数据加密

数据安全管控平台采用主流算法对敏感数据进行加密。

* 数据脱敏

全网安全运营员、各省中心/各部门安全运营者、省业务系统管理者需要对数据进行溯源查看或者因安全事件需要查看敏感数据外，其它角色用户敏感数据在界面展示时都要进行动态脱敏。

* 安全技术保障

1.在设计过程中的内部流程、开发规范、接口规范必须符合中国移动相关的安全规范和安全要求。

2.必须采用主流UNIX或Linux操作系统，并应使用成熟的、稳定的软件版本，不允许使用测试版本。
