服务提供商自我评估调查问卷 D 资格标准

服务提供商自我评估调查问卷（SAQ）D 适用于所有被支付品牌定义为合资格完成自我评估调查问卷的服务提供商。

***本 SAQ 是提供给服务提供商的唯一 SAQ 选项。***

## 确定帐户数据、持卡人数据和敏感验证数据

PCI DSS 适用于所有存储、处理或传输持卡人数据（CHD）和/或敏感验证数据（SAD）或可能影响持卡人数据环境（CDE）安全性的实体。持卡人数据和敏感验证数据被视为帐户数据，确定方式如下：

| 帐户数据 | |
| --- | --- |
| 持卡人数据包括： | 敏感验证数据包括： |
| * 主帐户号（PAN） * 持卡人姓名 * 到期日 * 业务码 | * 全磁道数据（磁条数据或芯片上的同等数据） * 卡验证代码 * PIN/PIN 数据块 |

欲了解更多详情，请参阅 PCI DSS 第 2 部分，PCI DSS 适用性信息。

## PCI DSS 自我评估完成步骤

1. 根据本 SAQ 中的资格标准以及 PCI SSC 网站上*的自我评估调查问卷说明和指南文件中的规定，本 SAQ 是提供给服务提供商的唯一 SAQ 选项。*
2. 确认服务提供商环境是否正确界定。
3. 评估环境是否符合 PCI DSS 要求。
4. 完成本文件的所有部分：
   * 部分 1：评估信息（遵从性证明书（AOC）的第 1 和第 2 部分–联系信息和执行摘要）。
   * 部分 2：
     + 2a – 关于被审查环境的细节。
     + 2b – 服务提供商专用自我评估调查问卷 D。

* 部分 3：认证和证明的细节（AOC 的第 3 和第 4 部分 - PCI DSS 不符合要求的认证和行动计划（如果第 4 部分适用））。

1. 提交 SAQ 和 AOC 以及任何其他要求的文件（例如 ASV 扫描报告）给要求的组织（管理遵从性计划的组织，例如支付品牌和收单机构）。

## 预期测试

载于“预期测试”一栏中的说明是基于 PCI DSS 中的测试程序，并具体描述了实体预期执行以核实某项要求是否得到满足的测试活动类型。

每个测试方法的目的描述如下：

* 检查：实体严格评估数据证据。常见示例包括文件（电子或物理），屏幕截图，配置文件，检查日志，和数据文件。
* 观察：实体观察其环境中的某些事物或动作。观察对象的实例包括执行任务或流程的人员、执行功能或响应输入的系统、环境条件和物理限制。
* 询问：实体与个别工作人员进行交谈。询问的目的可能包括确认是否执行了某项活动，描述如何执行某项活动，以及相关人员是否具有特定的知识或理解。

测试方法旨在让实体证明他们满足要求的具体方式。要检查或观察的特定项目和要询问的人员应该适合于被评估的要求和实体的特定实施。

可在 PCI DSS 中查询每项要求的测试程序的完整细节。

## 要求答复

对于每项要求项目，可以选择一个答复来表明实体在该要求方面的状态。***每项要求项目只应选择一个答复。***

下表解释了关于每个答复的含义以及如何报告所执行测试。

| 答复 | 什么时候使用这一答复： | 服务提供商  要求的报告 |
| --- | --- | --- |
| **已到位** | 已经执行了预期测试，并已按规定满足了要求的所有元素。 | 简要描述测试和证据如何证明要求“已到位” |
| **已到位并填写了 CCW**  （补偿性控制工作表） | 已经执行了预期测试，在补偿性控制的协助下满足了要求。 | 简要说明在要求的哪些方面使用了补偿性控制。  本栏中的所有答复还要求填写本 SAQ 附录 B 中的补偿性控制工作表（CCW）。  PCI DSS 中的附录 B 和 C 提供了关于使用补偿性控制的信息以及关于如何填写 CCW 的指南。 |
| **不适用** | 该要求不适用于该实体的环境。(示例详见下文“不适用要求的指南”。) | 简要描述证明要求“不适用”的测试结果  本栏中的所有答复还要求在本 SAQ 中附录 C 的支持性解释。 |
| **未测试** | 这项要求未被纳入评估的考虑范围，也没有以任何方式进行测试。(查看以下的“了解不适用和未测试之间的区别”，了解什么时候应该使用此选项的示例） | 简要说明为什么评估没有考虑这项要求。  本栏中的所有答复都要求在本 SAQ 中的附录 D 作出支持性解释。 |
| **未到位** | 要求中的一些或所有要素未得到满足，或正在实施中，或需要进一步测试，然后实体才能确认它们已到位。  如因法律限制而无法满足要求，也会使用该答复。(更多指南见下文“法律例外情况”)。 | 简要描述测试和证据如何证明要求“未到位”。  本栏的答复可能需要填写第 4 部分（如果提交本 SAQ 的实体要求）。  如果由于法律限制要求未到位，请描述禁止要求得到满足的法定法律或法规，并在本 SAQ 的第 3 部分填写相关证明。 |

不适用要求的指南

虽然许多完成 SAQ D 的实体需要认证是否符合每一项 PCI DSS 要求，但一些具有非常具体业务模式的实体可能会发现一些要求并不适用。例如，不以任何形式使用无线技术的实体预计不会遵守 PCI DSS中关于管理无线技术的具体要求。同样，在任何时候都不以电子方式存储任何帐户数据的实体，预计不会遵守与帐户数据安全存储有关的 PCI DSS 要求（例如，要求 3.5.1）。另一个示例是针对应用程序开发和安全编码的要求（例如，要求 6.2.1 至 6.2.4），这些要求仅适用于拥有订制软件（由第三方根据实体的规格为实体开发）或定制软件（由实体为自己使用而开发）的实体。

对于在本 SAQ 中选择“不适用”的每项答复，请填写附录 C：要求标记为“不适用”的解释。

了解“不适用”和“未测试”之间有何区别

必须认证被视为对某个环境“不适用”的要求。以上面的无线示例为例，如果实体要对要求 1.3.3、2.3.1、2.3.2 和 4.2.1.2 选择”不适用”，则首先需要确认无线技术是否没有用于其持卡人数据环境（CDE）中，无线技术是否也没有连接到其 CDE。一旦确认了这一点，组织可以为这些具体要求选择“不适用”。

如果一项要求被完全排除在审核之外，而没有考虑到它是否可以*适用*，则应该选择“未测试”答复。可能发生这种情况的示例可能包括：

* 收单机构要求实体认证要求的某个部分—例如，使用 PCI DSS 优先方法只认证某些里程碑。
* 实体正在确认仅影响到要求某个部分的新安全控制—例如，实施仅需要评估 PCI DSS 要求 2、3 和 4 的新加密方法。
* 服务提供商组织提供仅包括有限 PCI DSS 要求数量的服务—例如，物理存储提供商仅确认其存储设施符合 PCI DSS 要求 9 的实体安全控制。

在这些情况下，实体的评估只包括某些 PCI DSS 要求，尽管其他要求可能也适用于其环境。

如有任何要求被完全排除在实体的自我评估之外，请为该特定要求选择“未测试”，并填写附录 D：每个“未测试”条目的“要求未测试”的解释。含有任何“未测试”答复的评估是“部分”PCI DSS 评估，实体将在本 SAQ 第 3 部分的遵从性证明书中加以注明。

关于答复未来日期要求的指南

在下面的第 2 部分中，每项新的 PCI DSS 4.0版要求或具有延长实施期的项目符号都包括以下说明*：*“*此要求[或项目符号]在 2025 年 3 月 31 日之前是最佳实践，在此日期后被要求实施并且必须在 PCI DSS 评估中予以充分考虑。"*

在未来日期过去之前，这些新要求不需要包含在 PCI DSS 评估中。在该未来日期之前，商户尚未实施的任何具有延长实施日期的新要求可被标记为不适用，并记录在附录C中：要求标记为“不适用”的解释。

法律例外情况

如果您所在组织受到无法使其满足 PCI DSS 要求的法律限制，请为该要求选择“未到位”，然后在本 SAQ 部分 3 中填写相关证明。

**注：**法律限制是指满足 PCI DSS 要求会违反当地或地区的法律或法规。

合同义务或法律建议不是法律限制。

使用定制的方法

|  |
| --- |
| *SAQ 不支持使用定制的方法。* |

SAQ 不能用于记录使用定制的方法来满足 PCI DSS 要求。由于这个原因，定制的方法的目标不包括在 SAQ 中。希望使用定制的方法进行认证的实体可以使用 PCI DSS 遵从性报告（ROC）模板来记录其评估结果。

使用定制的方法可能受到管理遵从性计划的组织（例如，支付品牌和收单机构）的监管。有关使用定制的方法的问题应始终提交给这些组织。这包括符合资格填写 SAQ 的实体是否可以完成 ROC 以使用定制的方法，以及实体是否需要使用 QSA，或可以使用 ISA 来完成使用定制的方法的评估。有关使用定制的方法的信息可以查询 PCI DSS 中的附录 D 和 E。
