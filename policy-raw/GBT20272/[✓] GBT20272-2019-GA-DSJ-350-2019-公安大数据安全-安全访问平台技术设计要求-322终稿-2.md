公安大数据安全 安全访问平台技术设计要求

范围

本规范性技术文件规定了安全访问平台的安全体系、安全能力、部署方式，以及安全流程和性能设计要求。

本规范性技术文件适用于各级安全访问平台的规划、设计、建设、实施、运行等工作。

规范性引用文件

下列文件对于本文件的应用是必不可少的。凡是注日期的引用文件，仅注日期的版本适用于本文件。凡是不注日期的引用文件，其最新版本（包括所有的修改单）适用于本文件。

术语和定义、缩略语

术语和定义

GB/T 25069—2010、GA/DSJ 300-2019中界定的以及下列术语和定义适用于本文件。

安全访问平台 security access platform

新一代公安信息网（以下简称“公安网”）用户、其他网络访问数据中心的安全边界。该平台位于用户汇聚节点与数据汇聚节点之间，支持用户访问安全及数据交换安全两类服务。

安全基础设施 security infrastructure

公安大数据智能化立体化纵深防御体系的基础，安全大数据的重要数据来源和支撑。安全基础设施包括安全基础资源和安全资源服务，包括了身份管理、认证管理、权限管理及其他通用防护能力。

其他网络 other networks

公安网以外需与公安网进行信息交换和业务共享的网络，如社会企事业单位网络、党/政/军机关网络、电子政务外网、互联网等。

应用前置 application front-end

应用前后端分离后的应用前端部分。一般负责应用的界面展现，即用户从客户端浏览器看到的应用Web页面。

应用后置 application back-end

应用前后端分离后的应用后端部分。负责应用业务逻辑的处理。

数据服务 data service

数据中心的各类数据库、数据资源目录、数据接口等服务，供外部应用和服务调用。

令牌 token

身份认证请求的唯一标识符。

应用程序编程接口 application programming interface

一组基于服务或应用程序的标准和说明，能够与特定服务交互，包含了服务功能、访问使用方式及输入格式等。

虚拟桌面 virtual desktop

一种基于虚拟化技术所提供的桌面应用。用户使用终端设备进行交互操作，获得与传统个人电脑一致的用户体验。

略缩语

下列缩略语适用于本文件。

API 应用程序编程接口（Application Programming Interface）

DNS 域名系统（Domain Name System）

VPN 虚拟专用网络（Virtual Private Network）

WAF 应用防火墙（Web Application Firewall）

总则

设计原则

应用与数据分离原则

应用分离为应用前置、应用后置、数据服务三部分。应用前置进行页面展示；应用后置为应用前置提供业务处理逻辑并调用数据服务，从而实现应用与数据的分离。

应用中嵌入安全原则

用户访问数据的过程中建立多层防线，各层采用不同的防御技术进行监测和防护。应用访问、数据交换流程中嵌入强身份认证、权限控制及强审计，确保数据安全。

动态化访问控制授权原则

将用户、设备、应用和服务的身份抽象成实体身份，通过实体身份的属性进行认证和动态授权，持续监测评估终端、用户行为、网络等环境的安全状态，实现身份的持续认证及动态权限调整。

逐步改造迁移原则

现有应用系统应按应用与数据分离的原则逐步改造后迁入数据中心。无法立刻改造的应用，可基于原有的安全基础适度增强安全防护，继续留在原有数据中心。

弹性可扩展原则

根据安全需求通过集群等方式弹性扩展安全服务资源，通过服务接口以服务化的方式提供安全防护能力。

设计目标

根据公安大数据智能化总体规划及大数据安全总体技术框架要求，以安全、可信、合规为目标，建设统一的安全访问平台，实现访问用户的身份可信，确保业务仅对合法用户可见；结合业务场景和使用环境进行精细化的动态授权；保护数据安全访问，具备抵御网络攻击的能力；实现访问过程中用户行为及网络风险的全面发现与审计。

安全访问平台体系要求

平台框架

公安网通过安全访问平台将用户和数据中心隔离，分为用户访问安全、数据交换安全两类服务。用户通过安全访问平台访问数据中心，其他网络通过该平台与数据中心进行数据交换。

安全访问平台部署如图1所示。

图1 安全访问平台部署

安全访问平台是用户访问数据中心的统一边界通道。该平台可对用户发起的应用访问请求进行细粒度的管理和控制，阻止各类入侵行为和网络威胁，并进行数据泄露检测和应用保护。用户通过安全访问平台对数据中心资源进行操作，访问敏感数据时还需使用虚拟桌面，防止敏感数据流出数据中心。

安全访问平台是其他网络与数据中心交换数据的统一通道，通过该平台实现公安网与社会企事业单位网络、党/政/军机关网络、电子政务外网、互联网等其他网络之间的数据安全交换。

平台能力框架如图2所示。

图2 安全访问平台能力框架

平台服务能力要求如下：

1. 安全访问平台的用户访问安全服务具备用户接入安全、访问控制、链路通信加密、网络流量检测及网络安全防护等安全能力；
2. 数据交换安全服务具备设备准入控制、访问控制、网络流量检测、网络安全防护、安全隔离与交换等安全能力；
3. 相关安全能力应满足 GA/DSJ 300-2019及GB/T 20270-2006的要求。

用户访问安全能力

用户接入安全

用户包括公安网用户、公安驻地外用户以及其他网络用户。

公安网用户接入安全访问平台时，应通过安全基础设施的可信环境感知服务感知接入终端的安全状态，确保终端安全可信，实现安全接入。

公安驻地外用户和外部网络用户接入安全访问平台时，采用虚拟专网（VPN）技术接入安全访问平台，再通过安全基础设施的可信环境感知服务感知接入终端的安全状态，确保终端安全可信，实现安全接入。

链路通信加密

利用安全基础设施的网络传输加密服务进行链路通信加密，确保数据传输过程中的机密性、完整性。

访问控制

需实现网络访问控制、应用访问控制、应用接口访问控制三个方面的安全能力：

1. 网络访问控制：利用安全基础设施的网络访问控制服务，实现安全访问平台相关的网络访问控制，使用户和平台内部各组件只能访问已授权的网络资源；
2. 应用访问控制：在用户访问应用前置的过程中，支持单点登录，对用户身份进行统一验证，统一权限控制，确保应用系统访问入口的唯一性。综合利用安全基础设施的身份管理、认证管理、权限管理、可信接入代理、可信代理控制等服务实现动态访问控制；
3. 应用接口访问控制：在应用前置通过API接口调用应用后置的过程中，综合利用安全基础设施中的身份管理、认证管理、权限管理、可信API代理、可信代理控制等服务，实现应用前置与应用后端的接口访问控制。

网络安全防护

通过网络安全防护措施，实现网络入侵防御、网络恶意代码防护、应用攻击防护三方面的安全能力：

1. 网络入侵防御：利用安全基础设施的网络入侵防御服务，阻止或限制用户对数据中心的网络攻击和异常行为；
2. 网络恶意代码防护：用安全基础设施的恶意代码检测服务，对网络流量中的恶意代码进行检测和清除，降低恶意代码从用户终端扩散到数据中心的可能性；
3. 应用攻击防护：利用安全基础设施的应用安全防护服务，检测并阻止用户攻击Web应用的行为。

网络流量检测

利用安全基础设施中的相关安全服务检测网络流量，实现网络威胁检测、数据泄露检测、攻击诱捕三方面的安全能力：

1. 网络威胁检测：利用安全基础设施的网络威胁检测服务，采集、分析网络流量，发现网络攻击行为；
2. 数据泄露检测：利用安全基础设施的数据泄露检测服务，获取、还原、解析网络流量，检测数据传输过程中的敏感信息，防止数据泄露；
3. 攻击诱捕：利用安全基础设施的攻击诱捕服务，模拟网络环境，引诱攻击者进行攻击，发现攻击行为，分析攻击特征及攻击手法，拖延攻击进度，为攻击行为响应争取时间。

数据交换安全能力

设备准入控制

通过安全基础设施的网络准入服务，对其他网络接入安全访问平台的设备进行身份验证。

安全隔离与交换

在其他网络应用、服务与数据中心之间进行数据交换的过程中，应实现数据传输协议剥离、传输模式控制，并通过安全基础设施的隔离与交换服务，保证不同网络间的数据安全交换。

访问控制

网络访问控制：利用安全基础设施的网络访问控制服务，实现安全访问平台相关的网络访问控制，使其他网络应用和服务只能访问已授权的网络资源。

网络安全防护

通过网络安全防护措施，实现网络入侵防御、网络恶意代码防护两方面的安全能力：

1. 网络入侵防御：利用安全基础设施的网络入侵防御服务，阻止或限制对数据中心的网络攻击和异常行为；
2. 网络恶意代码防护：利用安全基础设施的恶意代码检测服务，对网络流量中的恶意代码进行检测和清除，降低恶意代码扩散到数据中心的可能性。

网络流量检测

通过检测网络流量，实现网络威胁检测、数据泄露检测、攻击诱捕三方面的安全能力：

1. 网络威胁检测：利用安全基础设施的网络威胁检测服务，采集、分析网络流量，发现网络攻击行为；
2. 数据泄露检测：利用安全基础设施的数据泄露检测服务，获取、还原、解析网络流量，检测数据传输过程中的敏感信息，防止数据泄露；
3. 攻击诱捕：利用安全基础设施的攻击诱捕服务，模拟网络环境，引诱攻击者进行攻击，发现攻击行为，分析攻击特征及攻击手法，拖延攻击进度，为攻击行为响应争取时间。

安全访问平台部署要求

整体部署

安全访问平台使用应用前置和应用后置分离的架构。应用前置进行页面展示。应用前置通过API接口调用应用后置，应用后置为应用前置提供业务处理逻辑并连接数据服务，从而实现应用与数据的分离。

安全访问平台建议采用双链路冗余，主要安全设备支持以集群等方式进行弹性扩展。

安全访问平台分区如图3所示。

![](data:image/png;base64...)

图3 安全访问平台分区示意图

安全访问平台在逻辑部署上可划分为安全防护区、用户接入区、应用前置区、接口访问区、安全检测区、数据交换服务区及安全管理区。其中：

1. 安全防护区实现平台与用户、平台与其他网络、平台与数据中心的网络隔离与防护；
2. 用户接入区实现用户的身份认证及可信环境感知；
3. 应用前置区实现应用前置的部署及应用安全防护；
4. 接口访问区实现对应用接口的动态访问控制及访问控制管理服务；
5. 数据交换服务区实现其他网络对文件、数据库、音视频等数据的交换服务；
6. 安全检测区实现对安全访问平台的综合安全检测和审计；
7. 安全管理区实现对安全访问平台的统一运维管理。

用户访问安全的相关能力主要部署在用户接入区、应用前置区及接口访问区，实现用户对应用、应用前置与应用后置之间的可信访问控制；数据交换安全的相关能力主要部署在数据交换服务区，实现其他网络对数据中心的数据安全交换。安全访问平台的逻辑部署结构参见附录A.1。

用户访问业务在逻辑上经过安全防护区的安全防护措施之后，依次经过可信接入代理、WAF、应用前置及可信API代理，进入应用后置并访问数据。可信环境感知与可信代理控制服务提供旁路的管理控制措施。

数据交换业务在逻辑上经过安全防护区的安全防护措施之后，完成设备准入控制，并通过数据交换服务的前后置系统、隔离与交换系统与数据中心完成数据交换。

此外，为了实现动态风险感知，需在终端部署终端环境感知客户端。安全访问平台需对接数据中心的认证服务、权限服务等安全基础设施，实现身份认证、授权等业务。可根据安全管理的需要，建立各级安全访问平台的环境感知及访问控制的统一管理服务。

用户访问安全

安全防护区

该区域实现对安全访问平台的边界保护。

部署统一威胁防护：在安全访问平台与用户汇聚节点、与数据汇聚节点之间部署统一威胁防护设备，实现对用户接入网络、数据中心网络的安全访问控制、网络入侵防护、网络恶意代码防护等安全能力。统一威胁防护限制其他网络设备各组件只能访问已授权的网络资源，阻止或限制用户的网络攻击和异常行为；对网络流量中的恶意代码进行检测和清除，降低恶意代码扩散的可能性。

用户接入区

该区域实现用户身份的安全认证及可信环境感知。

主要部署以下安全措施：

1. 可信接入代理：部署可信接入代理，验证终端设备、人员身份、应用身份的可信，实现应用的访问控制。可信接入代理在业务逻辑上处于用户与应用前置之间，通过可信代理控制服务完成访问主体的可信认证和访问控制；
2. 可信环境感知：部署可信环境感知系统，采集用户终端等用户身份属性、可信环境信息，实现所有风险项的权值分析，提供给可信代理控制服务以制定相应的安全策略；
3. 虚拟桌面：使用虚拟桌面实现用户对数据中心应用的增强安全访问。虚拟桌面用于外部用户访问普通业务、内部用户访问敏感业务的场景。外部用户和内部用户使用虚拟桌面应通过安全策略进行分组隔离。外部用户访问时，通过访问控制策略只允许接入虚拟桌面系统。

应用前置区

该区域实现应用安全防护，并部署应用前置及相关DNS服务等。应用前置由应用相关部门负责开发部署。

部署应用安全防护：部署WAF对应用前置的访问流量进行检测过滤，实现Web应用攻击防护、非授权访问防护、恶意代码防护、应用合规性审计防护等功能。WAF系统在业务逻辑上处于可信接入代理与应用前置之间。

接口访问区

该区域实现对应用接口的动态访问控制及访问控制管理服务。

主要部署以下安全措施：

1. 可信API代理：部署可信API代理，与可信代理控制服务结合，综合验证终端设备、人员身份、服务身份的可信，实现API接口的访问权限控制。可信API代理在业务逻辑上处于应用前置与应用后置之间，通过可信代理控制服务完成接口的可信认证和控制；
2. 可信代理控制服务：部署可信代理控制服务，为可信接入代理及可信API代理提供集中配置、集群管理、连接会话管理、访问授权判定、风险响应等能力。可信代理控制服务对接认证及权限等基础系统，接收用户接入区的环境感知信息进行综合判断分析。可信代理控制服务可管理和设置访问控制策略，基于风险、主客体等相关属性进行策略配置，下发到可信接入代理、可信API代理完成控制策略的执行。

数据交换安全

安全防护区

该区域实现对安全访问平台的边界保护。

部署统一威胁防护：在安全访问平台与其他网络之间部署统一威胁防护设备，接入其他网络链路，实现对其他网络的安全访问控制、网络入侵防护、网络恶意代码防护等安全能力。统一威胁防护限制其他网络设备各组件只能访问已授权的网络资源，阻止或限制对数据中心的网络攻击和异常行为。对网络流量中的恶意代码进行检测和清除，降低恶意代码扩散的可能性。

数据交换服务区

该区域实现其他网络对文件、数据库、音视频等数据的交换服务。安全访问平台通过安全防护区对各接入链路进行隔离，防止不同链路流量反向流出。

主要部署以下安全措施：

1. 设备准入控制：在其他网络的汇聚入口部署设备准入控制系统，针对外部设备提供身份验证等服务；
2. 数据交换服务：部署数据交换服务系统，包括前置和后置服务，对外提供统一资源调用等服务，对接入服务认证，满足数据库、文件、音视频等资源交换；
3. 安全隔离与交换：部署安全隔离与交换系统，阻断其他网络与数据中心之间的所有直接网络连接；对网络协议进行剥离，数据以专有数据块形式在网络间摆渡，保证网络安全隔离与数据安全交换。支持不同网络之间的安全隔离；支持不同网络之间的单向及双向数据传输；支持对网络流量的隔离和过滤防护，执行预定义的访问控制策略；支持对传输数据类型检查及过滤，执行预定义的黑白名单策略；可通过负载均衡和集群扩展的形式，确保服务的高可用性。

安全检测

安全检测区以旁路部署方式实现对安全访问平台的综合安全检测与审计。

主要部署以下安全措施：

1. 网络威胁检测：部署网络威胁检测系统，采集、分析安全访问平台内各区的网络流量，发现网络攻击行为；
2. 数据泄露检测：部署数据泄露检测系统，获取、还原、解析安全访问平台的网络流量，检测数据传输过程中的敏感信息，防止数据泄露；
3. 攻击诱捕：部署攻击诱捕系统，模拟网络环境，引诱攻击者进行攻击，发现攻击行为，分析攻击特征及攻击手法，拖延攻击进度，为攻击行为响应争取时间；
4. 日志采集：部署日志采集系统，采集安全访问平台中网络设备、安全设备、应用系统等安全相关日志信息。经过预处理后，统一发送至安全大数据平台；
5. 安全漏洞扫描：部署安全漏洞扫描系统，对安全访问平台内的服务器、应用前置等系统、组件进行安全检查，发现漏洞、配置违规问题，提供安全加固支撑；
6. 用户行为分析：部署用户行为分析系统，采集安全访问平台的用户行为，关联用户与实体的日志数据，分析用户及实体异常行为，解决不合格操作、访问滥用、蓄意破坏和篡改、内部缓慢攻击、内部持续渗透等问题。

用户访问普通应用流程

用户访问普通应用的总体流程如图4所示。

![](data:image/png;base64...)

图4 用户访问普通应用流程

具体流程包括：

1. 用户通过终端访问应用，访问请求重定向至可信接入代理；
2. 可信接入代理通过可信代理控制服务进行用户身份认证、可信风险的感知及应用授权；可信代理控制服务到认证授权系统进行身份认证，认证通过后进行应用权限授权，并颁发用户Token；

5. 鉴权通过后，可信API代理转发API接口调用至数据中心的应用后置/接口服务；
6. 应用后置/接口服务调用数据，用户成功访问应用。
7. 在用户访问过程中，可信环境感知系统实时感知外部环境风险，结合可信代理控制服务进行风险判定，基于风险判定结果做动态阻断等相应操作。

数据交换服务流程

以党/政/军等单位数据交换业务为例，流程如下：

1. 党/政/军等单位与数据中心有数据交换需求时，通过设备准入完成对党/政/军等单位应用或服务的认证鉴权，获取相关权限；
2. 党/政/军等单位应用或服务发起数据交换请求，将数据发送至数据交换服务的前置机；
3. 数据交换服务的前置机根据交换数据的安全策略，对数据进行格式检查、内容过滤，并将数据传输给隔离与交换系统；
4. 隔离与交换系统剥离网络协议，检查数据完整性，将数据摆渡到数据交换服务的后置机，进行数据校验，并进行交换记录的安全审计；
5. 数据交换服务的后置机基于访问控制策略将数据推送至数据中心；
6. 在需要向外部传递数据的情况下，数据交换服务的后置机接收来自数据中心的数据，对数据进行格式检查、内容过滤，并将数据传输给隔离与交换系统；
7. 隔离与交换系统剥离网络协议，检查数据完整性，将数据摆渡到数据交换服务的前置机，进行数据校验，并进行交换记录的安全审计；
8. 数据交换服务的前置机将数据推送给党/政/军等单位。

性能设计要求

用户访问时延

安全访问平台的用户访问时延应小于300 ms。

数据交换能力

安全访问平台的文件交换性能应不低于10 Gbps。

安全访问平台数据库同步性能每秒应不低于10000条（数据库记录小于10 kB）。

安全管理要求

安全运维要求

安全运维要求包括：

1. 应按照公安网的有关规定和要求，建立健全本级安全访问平台的运维管理制度和工作制度；
2. 应根据事件的等级制定相应的应急预案，定期对重要数据进行备份；
3. 应设立专用区域作为安全访问平台的运维场所。

应用改造要求

应用改造要求包括：

1. 新建应用系统应遵循应用与数据分离的原则，按照应用前置、应用后置、数据服务的结构进行规划、设计、开发和部署；
2. 现有应用系统应按照应用前置、应用后置、数据服务的结构进行改造，改造完成后方可通过安全访问平台进行访问。不能改造的应用系统，延用原访问通道继续提供服务；
3. 应用改造由应用系统主管部门负责。

测评要求

测评要求包括：

1. 安全访问平台测评标准应依据本规范及相关技术要求制定；
2. 安全访问平台应通过有关测评和检测。
