#### 引 言

数据安全是各国当下关心的主题，数据安全管理认证是构筑网络运营者和其客户的信息的有效桥梁，是网络运营者证明其履行社会责任，遵守国家法律要求的重要手段，实施数据安全管理认证首先需要建立认证依据，编制数据安全基本要求是开展数据安全管理认证的基础。

到目前为止，数据安全相关的国际国内标准已陆续发布，主要包括GB/T22080-2016/ISO/IEC 27001:2013《信息安全管理体系 要求》、GB/T35273-2017《信息安全技术 个人信息安全规范》、GB/T35274-2017《信息安全技术 大数据服务安全能力要求》、ISO 27701-2019《安全技术—隐私信息管理的ISO / IEC 27001和ISO / IEC 27002的扩展—要求和准则》和GB/T 37988-2019《信息安全技术 数据安全能力成熟度模型》，但这些要求尚未形成完整而独立的面向网络运营者的数据安全要求，主要是因为各自关注的重点不同，相对组织对信息安全的保障，数据安全有其特殊属性，这主要是数据安全的保障对象的主体和控制者多样性，信息安全保障的对象信息资产组织是控制者，而数据安全的保障对象数据其主体与控制者则可能是个人、组织和国家，首先要从国家层面看，重要数据安全需要加以重视，重要数据的控制者是国家或关键机构或网络运营者，做好重要数据安全保护是网络运营者的首要责任，这些往往通过法规要求；再则要从公众的利益角度看，特别是个人信息的保护，个人信息则其主体是公众，控制者可能是个人、网络运营者，做好个人信息保护是一个网络运营者应尽的义务；网络运营者自身的运营数据其主体可能是自己的，也可能是国家的、也可能是公众的，而控制者是网络运营者，也可能是其他网络运营者的，组织自身的数据安全保障需求往往很复杂，因此，数据安全管理认证与其他管理认证的最大差异是其他管理认证侧重的是向其产品和服务的接受方证明自身的管理水平，以增强其信心，而数据安全管理认证则要向国家、公众和与数据相关的服务接受方（往往不是数据本身）证明其数据安全管理水平，以增强大家的信心，认证的广度和深度的要求都更高，而组织的积极性却可能更低，认证机构所承担的责任则可能更大，建立一套合适的数据安全基本要求成了提升大家的认证积极性和降低认证风险的重要一环。

为贯彻落实《数据安全管理办法》，实施数据数据安全管理认证制度，参考有关国家标准和国际标准制定本标准。

# 数据安全基本要求

# 范围

本标准阐述了网络运营者在数据收集、数据传输、数据保存、数据处置、数据使用、数据共享、转让与委托处理、公开披露、数据出境、第三方服务接入等活动中的活动管理和安全控制要求，以及为安全控制要求得到持续有效实施的相关管理活动要求。提出了参考的典型控制。

本标准的数据包括个人信息（含敏感信息）、重要数据和组织运营（业务）数据。

本标准为数据安全管理认证提供依据，同时也可为网络运营者提高自身数据安全保障水平，建立数据安全管理体系提供指引，也可作为数据安全监管机构对网络运营者进行监管时参考使用；。

符合以下条件之一的网络运营者宜满足本标准的要求：

1. 收集或保存、处置超过100万用户个人信息的；
2. 委托处理个人信息的；
3. 共享、转让和公开披露个人信息的；
4. 收集或保存、处置重要数据的；
5. 委托处理重要数据的；
6. 共享、转让和公开披露重要数据的；
7. 提供第三方应用接入平台服务的；
8. 涉及数据出境的。

# 术语、定义和缩略语

GB/T 35273和GB/T 22080界定的以及下列术语和定义适用于本标准。

## 网络运营者 network operator

网络的控制者、管理者和网络服务提供者。

## 重要数据 critical data

是指一旦泄露可能直接影响国家安全、经济安全、社会稳定、公共健康和安全的数据，如未公开的政府信息，大面积人口、基因健康、地理、矿产资源等。重要数据一般不包括企业生产经营和内部管理信息、个人信息等。

## 数据提供方 data provider

数据共享、交易、委托处理过程中提供数据的组织或者自然人。

## 数据接收方 data receiver

数据共享、交易、委托处理过程中接受数据的组织或者自然人。

## 个人信息 personal information

以电子或者其他方式记录的能够单独或者与其他信息结合识别自然人个人身份的各种信息，包括但不限于自然人的姓名出生日期、身份证件号码、个人生物识别信息、住址、电话号码等。

## 个人敏感信息 personal sensitive information

一旦泄露、非法提供或滥用可能危害人身和财产安全，极易导致个人名誉、身心健康受到损害或歧视性待遇等的个人信息。

## 数据主体data subject

数据所标识的个人、组织或关联到的自然人和组织，特别能够标识的个人和关联到自然人为个人信息主体。

## 数据活动 data active

网络运营者业务运营过程中与数据相关的活动，包括数据收集、收集保存、数据处置、数据使用、数据共享、转让和公开披露、数据委托处理等。

## 数据控制者 data controller

能单独或联合决定数据的处理目的和方式的自然人、法人、公共机构、代理机构或其他组织。

## 数据处理者 data processor

为控制者处理数据的自然人、法人、公共机构、代理机构或其他组织。

## 数据接收者 data recipient

接收到被披露的数据的自然人、法人、公共机构、代理机构或其他组织，无论其是否为第三方。

## 第三方 third party

数据主体、控制者、处理者以及由控制者或处理者直接授权处理个人数据的人以外的自然人、法人、公权力机构、代表机构或其他组织。

## 自评价 self-evaluation

申请组织根据认证依据对自身的服务过程进行符合性评价，并进行评价证据的收集和分析，以确定组织满足认证依据的程度。

# 确定数据保护范围

## 识别需要保护的数据

网络运营者应识别数据运营中涉及的个人信息（包括个人敏感信息）、重要数据和运营数据，形成数据保护清单。数据保护清单至少包括以下内容：

1. 列入数据保护范围的产品、服务和系统；
2. 产品、服务和系统包含的业务功能和业务功能所需的数据，及其数据的作用和数量（个人信息以用户数计，重要数据、运营数据以字节数计，下同）；
3. 对数据进行归类，数据分为个人信息（包括注明个人敏感信息），重要数据和运营数据。

## 识别数据活动

网络运营者应逐项识别数据保护清单中数据的活动以及实现方式（数据保护清单示例见附录B.1数据保护清单示例-数据识别），并维护数据保护清单，维护内容包括：

1. 数据的收集方式、收集频率、保存方式、保存期限、保存位置、处置方式；
2. 数据传输发送方和接收方以及传输的方式；

注：发送方和接收方可以是内外部的人、组织、系统和设备。

1. 数据共享、转让和发布的目的、对象、范围和方式；
2. 数据委托处理的数据活动、委托处理的目的、对象、数量、期限；
3. 数据是否用于用户画像、个性化展示、自动决策、自动合成和标识个人信息主体行为；
4. 数据提供给个人信息主体的查询、修改、删除、授权撤销、申述和投诉、活动停止请求等活动的方法；
5. 数据出境的目的、数量，数据接收方；
6. 上述内容如不适用时应给出说明。

网络运营者在使用数据保护清单之前，数据保护清单应得到评审，确保数据清单内容充分适宜，并在适当范围内进行（公开）发布。网络运营者应定期（最长不超过12个月）或在清单涉及的内容发生变化时对数据保护清单进行更新。

数据保护清单示例见附录B.2数据保护清单示例-活动识别。

## 确定范围

网络运营者应在数据保护清单的基础上确定数据保护范围，原则上数据保护范围应覆盖数据清单识别的所有的数据，如果不覆盖所有数据应说明理由。网络运营者应对数据保护范围的适宜和充分进行评审，并在组织范围内发布。

# 数据安全保护目标和计划

## 数据安全保护目标

网络运营者应根据数据保护清单，梳理本标准中适用的要求，并根据每一条要求确定每类数据和每项数据活动的数据安全保护目标，形成数据安全保护目标文件（数据安全保护目标文件示例见附录B.3数据安全保护目标示例）。

数据安全保护目标文件应针对本标准的每一条要求，确定如下内容：

1. 明确为满足要求应达到的结果，结果应可呈现，如发布隐私声明，任命数据安全责任人等；
2. 必要时，包括实现上面结果的时效、质量指标，如事件响应时间，个性化推送服务的用户满意度等，这些指标应可测量；
3. 不适用时，说明不适用的理由。
4. 典型的数据安全保护目标包括但不限于:
   1. 建立专门的数据安全管理组织；
   2. 任命专职数据安全保护官；
   3. 所有数据安全保护职责定义明确并分配到岗，确保相关人员有能力信任其工作；
   4. 制定、维护并发布隐私政策，政策满足本标准的内容要求；
   5. 基于最小收集原则，明确合法、合规、合理的收集范围，且超范围收集事件为0；
   6. 确保数据传输过程中，数据不丢失、不被篡改、个人敏感信息和重要数据实现100%的采用符合密码法要求的加密传输；
   7. 确保存储的数据不丢失、不损毁、不被篡改、个人敏感信息100%脱敏或采用符合密码法要求的加密保存，重要数据100%采用符合密码法要求的加密保存，运营数据按网络运营者定义的级别确定适宜的采用符合密码法要求的加密机制；
   8. 数据处置按计划的时间处置及时率100%，在未处置之前应采取措施确保，不因未及时处置造成数据丢失和滥用、误用；
   9. 基于数据主体授权同意和最小使用原则，明确合法、合规、合理的使用范围和方式，且超范围使用、不正当使用事件为0；
   10. 不因数据共享、转让和委托处理而引起数据泄露和不正当使用；
   11. 出境数据出境按相关管理办法要求，实施出境前审查率100%，且违规出境事件为0；
   12. 不因第三方应用接入引起数据泄露和不正当使用；
   13. 所有事件得到记录、报告和及时处理。

网络运营者应依据数据保护清单涉及的数据和活动，确定每一个方面应达到目标。

## 数据安全保护计划

数据安全保护责任人应对组织实现数据安全保护目标进行策划，策划的内容包括：

1. 数据安全保护组织的策划，确定数据安全保护的相关部门、岗位与人员，将数据安全保护目标的责任落实到部门、岗位与人员，并形成文件；
2. 数据安全影响分析和风险评估的策划，确定安全影响分析和风险评估方法与程序，所确定的方法应该是可比较和可再现的，将相关责任落实到部门，并形成文件，确保定期（最长不超过12个月）和组织、组织环境及其数据活动发生重点变化时，进行安全影响分析和风险评估，并形成报告；
3. 数据安全保护差距分析策划，确保定期（最长不超过12个月）和组织、组织环境及其数据活动发生重点变化时，能够及时识别并评审数据安全保护目标的实现情况，掌握实际存在的差距，形成数据安全保护差距分析报告；
4. 数据安全保护措施策划，根据数据安全影响分析和风险评估以及差距分析的结果，决定组织应采取的数据安全保护措施，形成措施清单；明确措施的有效性评价指标；
5. 数据安全持续改进策划，确保措施有效性得到监视和测量，定期（最少每月）形成监视和测量报告；确保定期（最长不超过12个月）和组织、组织环境及其数据活动发生重点变化时，实施一次自评价和管理评审，已确定组织的数据安全保护目标的实现程度和措施实施的有效性，形成有效性测量、自评价和管理评审报告。

网络运营者应依据策划文件，制定数据安全保护计划，计划的内容应包括：

1. 数据安全保护需要执行的活动和目前已开展的活动；
2. 需要设计和实施的活动，活动及活动接口执行的角色、权力和责任；
3. 活动需要的人力资源，包括人员及人员能力需求（教育、培训、技能和经验需求）；
4. 活动需要的财务资源；
5. 活动需要使用的技术；
6. 活动需要的外部支持及相关协议；
7. 活动输出结果的形式；
8. 活动的具体评价指标和评价方法；
9. 数据安全保护活动的实施时间安排和步骤等。

网络运营者应数据安全保护计划的适宜和充分进行评审，并在适当范围内发布。

网络运营者应按照数据安全保护计划实施数据安全保护。

网络运营者应对策划文件和保护计划的变更应进行评估和批准，并在批准后发布。

数据安全保护计划内容示例见B.4数据安全保护计划示例。

# 制定隐私政策

## 概述

网络运营者应针对数据保护清单的数据活动制定隐私政策，并对其进行管理。

## 隐私政策内容

网络运营者在制定隐私政策时，应至少包括：

1. 网络运营者的基本情况，包括主体身份、联系方式；
2. 产品和服务包含的功能，为实现每项功能必须收集的个人信息，收集这些信息的目的，涉及个人敏感信息的，需明确标识或突出显示；
3. 个人信息的收集方式、保存期限和到期后的处置方式；
4. 收集的个人信息的使用范围、用途以及是否向境外提供；
5. 提供个人信息后可能存在的安全风险，及不提供个人信息可能产生的影响（后果）；
6. 个人信息主体的权利和实现机制，如查询方法、更正方法、删除方法、注销账户的方法、撤回同意的方法、获取个人信息副本的方法、对信息系统自动决策结果进行申诉的方法等；
7. 处理个人信息主体询问、投诉的渠道和机制，以及外部纠纷解决机构及联络方式；
8. 遵循的个人信息安全基本原则，具备的数据安全能力，以及采取的个人信息安全保护措施，必要时可公开数据安全和个人信息保护相关的合规证明。

## 隐私政策管理

网络运营者应对隐私政策进行管理，具体包括：

1. 应对隐私政策进行评审，确保隐私政策所告知的信息真实、准确、完整，描述清晰易懂，符合通用的语言习惯，在内容描述上使用标准化的数字、图示等，避免使用有歧义的语言；
2. 隐私政策应逐一送达个人信息主体，当成本过高或有显著困难时，可以公开形式发布，隐私政策应易于访问，且个人信息主体可通过公开渠道获得；
3. 当法律法规要求和合同约定发生变化时或当数据活动发生重大变化时，对隐私政策进行评审，发现问题及时进行修订；
4. 在隐私政策包含的事项发生变化时，应及时重新告知个人信息主体；
5. 隐私政策内容应在网络运营者的网站和应用程序的功能设计等管理和运营活动中得到实施。

# 数据收集管理与安全控制

## 数据收集的授权同意

网络运营者在进行数据收集前，应依据以下要求向国家相关部门备案或数据主体（特别是个人信息主体）的授权同意，包括：

1. 网络运营者收集重要数据或收集个人敏感信息涉及人数超过100万人的，应向所在地网信部门备案，保留备案记录。备案内容包含收集使用的目的、规模、方式、范围、用途 和保存期限，以及是否向他人提供、向境外提供等；
2. 网络运营者收集其他数据主体控制者的数据时，应向与数据控制者达成协议。协议内容包含收集使用的目的、规模、方式、范围、用途 和保存期限，以及是否向他人提供、向境外提供等；
3. 网络运营者在个人信息收集前应向个人信息主体告知并获得同意，包括：
4. 告知收集、使用的目的、用途、方式和范围，并获得个人信息主体的授权同意；
5. 当产品或服务提供多项需收集个人信息的业务功能时，网络运营者不应违背个人信息主体的自主意愿，强迫个人信息主体接受产品或服务所提供的业务功能及相应的个人信息收集请求。网络运营者：
   * + 不应通过捆绑产品或服务各项业务功能的方式，要求个人信息主体一次性接受并授权同意各项业务功能收集个人信息的请求。
     + 应把个人信息主体自主选择行为，如主动点击、勾选、填写等，作为产品或服务的特定业务功能的开启条件。网络运营者应仅个人信息主体开启该业务功能且符合本节b. 1)的要求后，开始收集个人信息；
     + 关闭或退出业务功能的途径或方式应与个人信息主体选择使用业务功能的途径或方式同样方便。个人信息主体选择关闭或退出特定业务功能后，网络运营者应停止该业务功能的个人信息收集活动；
     + 个人信息主体不同意使用、关闭或退出特定业务功能的，不应频繁征求个人信息主体的同意；
     + 个人信息主体不同意使用、关闭或退出特定业务功能的，不应暂停个人信息主体自主选择使用的其他业务功能，或降低其他业务功能的服务质量。
6. 收集个人敏感信息前，征得个人信息主体的明示同意，明示同意的选项应与个人敏感信息收集需求在一个界面中显示，且通过二次确认，确保个人信息主体的明示同意是其在完全知情的基础上自主给出的具体、清晰、明确的意愿表示。
7. 网络运营者在间接获取个人信息时应确保信息合法且获得个人信息主体的授权同意，包括：
   1. 获得个人信息提供方个人信息来源说明以及信息来源的合法性有效证明，确定个人信息提供方已获得的个人信息处理的授权同意范围，确认个人信息主体是否授权同意个人信息提供方可对其他方提供信息；
   2. 网络运营者开展业务所需进行的个人信息处理活动超出个人信息主体授权同意范围的，在获取个人信息后的合理期限内或处理个人信息前，征得个人信息主体的授权同意，授权同意应满足本节b )条款的要求。

## 数据收集安全措施

在数据收集过程中，网络运营者应对数据收集活动进行影响分析和风险评估，根据其结果采取适当的安全措施确保数据安全，具体包括：

1. 仅收集数据保护清单列明的数据；
2. 通过APP或WEB界面进行数据采集时，应做到：
3. APP或WEB界面的开发时，应将数据保护清单和隐私政策的内容实现融合到整个产品和服务的开发设计、编码和测试中，并建立和实施安全开发控制过程，形成记录；
4. 对重要数据和个人敏感信息进行加密或脱敏处理，网络运营者为数据主体的数据按其自身的等级加密或脱敏策略进行处理;
5. APP、WEB等客户端不应留存个人敏感信息及重要数据、并及时清理缓存。
6. 通过纸质表单收并转换为电子信息时，应做到：
7. 表单的内容设计与数据保护清单和隐私政策中约定收集的内容保持一致；
8. 表单的保存、传输、查阅、复制等操作进行权限控制，未经授权不得进行上述操作，涉及个人敏感信息和重要数据的上述操作，应得到特别审批。
9. 采取自动化手段从网站或其他公开数据库间接收集或获取重要数据时，应考虑网站和其他公开数据库的数据处理能力和网络承载能力，不能影响网站和公开数据库的正常运行；
10. 个人敏感信息和重要数据收集过程应有完整的记录或日志，确保可查、可追溯。

# 数据传输管理与安全控制

网络运营者应对数据传输活动进行管理，必要时采取相关措施，确保数据传输活动得到控制，包括：

1. 仅按照数据保护清单列明的数据及数量，从数据发送方向数据接收方，以确定的传输方式传输数据；
2. 对传输过程可能造成的影响应进行分析，实施风险评估，并根据需要采取相关措施；
3. 传输个人敏感信息和重要数据时，必须进行加密。

# 数据保存管理与安全控制

网络运营者应对数据保存活动进行管理，必要时采取相关措施，确保数据保存活动得到控制，包括：

1. 仅按照数据保护清单列明的数据及数量，确定的保存方式和期限保存数据；
2. 应对数据保护清单的数据保存位置（介质和物理位置）进行标识，形成列表，并定期（最长半年）对数据保存位置进行核查，确保实际保存位置与列表信息保持一致；
3. 对数据保存过程中可能产生的影响应进行分析，实施风险评估，并根据需要采取相关措施；
4. 应对个人信息进行去标识化处理，如果需要进行重新标识化，去标识化后的信息和用于恢复识别个人信息的数据应分别存储，且严格控制对两类数据同时访问的权限；
5. 应对个人敏感信息和重要数据进行加密保存，网络运营者为数据主体的数据按其自身的等级加密或脱敏策略决定是否进行加密保存；
6. 应对个人生物识别信息，建立其摘要，并将摘要信息和原始信息分开保存，严格控制对两类数据同时访问的权限；
7. 应建立备份策略，依据策略进行备份，并对备份进行测试以确保备份可用；
8. 使用移动介质保存数据时：
   1. 对使用的移动介质进行授权管理，只有经授权的移动介质可用于保存保护范围内的数据；
   2. 授权内部使用的移动介质不允许设置自动读取，且在使用前进行安全扫描；
   3. 授权内部使用的移动介质不得在非授权设备上使用；
   4. 移动介质中存放的个人敏感信息和重要数据应进行加密存储。
9. 使用内部网络环境的设备保存数据时，应对内部网络环境进行适当的安全防护，确保数据安全，包括：
   1. 保存数据的设备应存放于有访问控制和基础设施环境管理的空间内；
   2. 应根据设备需要定期对设备进行维护；
   3. 对于保存重要数据和个人敏感信息的设备所在的网络布线进行控制，确保对网络线路和接口的访问得到控制；
   4. 保存数据的设备应在独立的网段内，对该网段的访问需要明确的授权；
   5. 保存数据的网络应与互联网进行隔离；
   6. 适用时，保存数据的网络应与开发测试环境隔离；
   7. 应对保存数据的网络进行监控，发现异常及时进行处理；
   8. 应对保存数据的网络进行冗余备份。
10. 使用外部租赁的网络存储环境保存数据时，应与存储环境提供方签订合同，并在合同中明确存储环境的安全要求，安全要求不低于本标准的保护要求，并通过监视确认存储环境提供方能够持续提供达到要求的网络存储环境。

# 数据处置管理与安全控制

网络运营者应对不需要再保存的数据的处置活动进行管理，必要时采取相关措施，确保数据处置活动得到控制，包括：

1. 仅按照数据保护清单列明的数据及数量，确定的处置方式处置数据；
2. 对数据处置过程中可能产生的影响应进行分析，实施风险评估，并根据需要采取相关措施；
3. 重要数据超出保存期限或产品和服务停止运营时，应被及时删除；
4. 个人信息超出保存期限、产品和服务停止运营、用户注销账户、个人信息主体撤回同意时，应及时被删除或匿名化处理；
5. 数据过保存期限、产品和服务停止运营、用户注销账户、个人信息主体撤回同意时，法律法规和合同有明确的要求的，按照法律法规和合同要求进行处理；
6. 对存储个人敏感和重要数据的介质进行报废处理时，应采用物理破坏的方式进行数据处理，以确保数据不能被恢复，报废处理过程应进行跟踪和监督；
7. 对数据处置的过程应进行记录，确保重要操作可追溯。

# 数据使用管理与安全控制

## 数据使用管理

### 使用授权

网络运营者应确保个人信息的使用在个人信息主体的授权范围内，其他数据主体控制者的数据使用应确保在与数据控制者达成协议范围内，防止不当使用，包括：

1. 网络运营者应在数据保护清单确定的范围，且经个人信息主体的授权同意范围内，其他数据主体控制者的数据使用应确保在与数据控制者达成协议范围内，使用信息；
2. 通过数据处理产生的信息如果可以单独或与其他信息结合识别个人信息主体，信息的使用应在个人信息主体的授权范围内；
3. 网络运营者应定期（最长不超过6个月）对数据的使用情况进行审计，确保数据的使用与授权的数据使用目的、方式和范围保持一致。

### 用户画像使用

网络运营者应对用户画像的使用进行管理，包括：

1. 用户画像中对数据主体（特别是个人信息主体）的特征描述，不应：
2. 包含淫秽、色情、赌博、迷信、恐怖、暴力的内容；
3. 表达对民族、种族、宗教、残疾、疾病歧视的内容。
4. 在业务运营或对外业务合作中使用用户画像的，不应：
5. 侵害保护公民、法人和其他组织的合法权益；
6. 危害国家安全、荣誉和利益，煽动颠覆国家政权、推翻社会主义制度，煽动分裂国家、破坏国家统一，宣扬恐怖主义、极端主义，宣扬民族仇恨、民族歧视，传播暴力、淫秽色情信息，编造、传播虚假信息扰乱经济秩序和社会秩序。
7. 除为达到个人信息主体授权同意的使用目的所必需外，使用个人信息时应消除明确身份指向性，避免精确定位到特定个人。例如，为准确评价个人信用状况，可使用直接用户画像，而用于推送商业广告目的时，则宜使用间接用户画像。

### 个性化展示

利用个人信息开展个性化展示服务时，网络运营者应确保个人信息主体可以选择不接受个性化推送或者对个性化展示进行选择，包括：

1. 在向个人信息主体推送新闻信息服务的过程中使用个性化展示的，应为个人信息主体提供简单直观的退出或关闭个性化展示模式的选项；
2. 电子商务经营者根据消费者的兴趣爱好、消费习惯等特征向其提供商品或者服务搜索结果的个性化展示的，应当同时向该消费者提供不针对其个人特征的选项；
3. 关闭个性化推送和个性化展示后，应删除已经收集的以个人化展示为目的的用户数据和个人信息或做匿名化处理。

### 自动决策

数据运营所使用的信息系统，具备自动决策机制且能对数据主体（特别是个人信息主体）权益造成显著影响的（例如自动决定个人或组织征信及贷款额度，或用于面试人员的自动化筛选、供应商选择等），应向数据主体（特别是个人信息主体）提供针对自动决策结果的申诉渠道，并对自动决策结果进行人工复核。

### 公开信息的自动合成

利用数据合成信息时，网络运营者应确保不对社会、第三方和个人的合法权益造成影响，具体要求如下：

1. 使用大数据和人工智能等技术，通过算法自动合成的新闻、博文、帖子、评论等，应以明显方式标明“合成”字样，并注明数据来源；
2. 自动合成的新闻、博文、帖子、评论等应不以谋取利益为目的，且不损害个人合法权益。

## 数据使用安全控制

### 数据访问控制

网络运营者应对数据的访问进行控制，具体要求如下：

1. 对数据保护范围内的数据按照其分类，明确相关人员的访问权限，采取措施使得相关人员只能按授权访问数据；
2. 对访问权限的分配进行审批，明确访问权限分配和回收的审批责任人；
3. 对个人敏感信息、重要数据和网络运营者自身确定的高级别数据的访问权限分配由数据安全责任人或其授权委托人进行审批；
4. 对数据的访问权限和实际访问控制情况进行定期（最长不超过6个月）评审，发现问题及时改进；
5. 对访问数据使用的身份鉴别信息做出具体要求，如访问个人信息使用的口令应满足的要求、生物技术的使用要求等。

### 数据展示控制

网络运营者应对数据的展示进行控制，仅在必要时对必要的人展示必要的信息，具体要求如下：

1. 识别界面展示需求（包括展示的条件、展示的对象和展示的内容），分析界面展示必要性，形成记录；
2. 针对需要展示的内容和展示对象，确定具体的展示方式，并定期（不超过3个月）对数据展示进行抽查，如果采用技术手段进行展示控制，应定期（不超过6个月）对技术手段进行核查，确保按确定的展示方式，向确定的对象展示必要的内容；
3. 展示时对需要脱敏的数据采取脱敏方式进行展示；
4. 对仅供展示的数据，采取措施对数据实施保护，避免展示的数据被查看人员的不正当收集、保存、处置等。

## 履行个人信息主体权益保护义务

### 响应个人信息主体的请求

网络运营者应对个人信息主体的请求进行管理，及时做出响应，具体要求包括：

1. 形成请求响应清单，包括请求响应的类型、响应方式、响应过程、响应和处理条件、响应和处理时间以及不予响应的请求类型，条件和原因；
2. 响应的请求至少包括个人信息查询、个人信息更正、个人信息处理活动停止请求、个人信息删除请求、撤回同意、注销账户、获取个人信息副本、申诉、投诉和咨询；
3. 在相关法律法规、合同或数据请求响应清单发生变化时，对请求响应清单进行修订和评审；
4. 个人信息主体的请求方法应简单易操作；
5. 建立过程对未识别的个人信息主体的请求进行处理，确保未识别的合理合法的请求得到响应；
6. 请求响应清单应以明显的方式进行公布，必要时逐一送达个人信息主体，为个人信息主体提供请求指导，例如通过发布操作流程和提供咨询电话；
7. 在处理请求时，网络运营者应在响应请求之前，确认请求者身份。

### 个人信息查询

网络运营者应向个人信息主体提供下列信息查询的方法：

1. 其所持有的关于该主体的个人信息或个人信息的类型；
2. 上述个人信息的来源、所用于的目的；
3. 已经获得上述个人信息的第三方身份或类型。

### 个人信息处理活动停止

个人信息主体对网络运营者的个人信息处理提出反对时，如果网络运营者没有充足的理由支持其处理，在收到正式的反对意见后，应立即停止相关处理活动。

### 个人信息删除

以下情况，个人信息主体申请删除信息的，网络运营者应予以支持，具体要求如下：

1. 网络运营者违反法律法规规定，收集、使用个人信息的，应立即删除个人信息；
2. 网络运营者违反与个人信息主体的约定，收集、使用个人信息应立即删除个人信息；
3. 网络运营者违反法律法规规定或违反与个人信息主体的约定向第三方共享、转让个人信息的，应立即停止共享、转让，并通知监督共享、转让的数据接收方删除个人信息；
4. 网络运营者违反法律法规规定或违反与个人信息主体的约定，发布个人信息的，应立即停止发布行为，删除发布的信息；
5. 与个人信息主体约定的数据收集和使用目的不再需要该个人信息的，应删除个人信息。

### 授权撤销

个人信息主体申请撤销授权时，网络运营者应予以支持，具体要求如下：

1. 个人信息主体申请撤销授权时，应告知其影响和个人信息的处置方式；
2. 个人信息主体有多项授权时，应提供授权撤销的选择，个人信息主体撤回授权后，应停止相关个人信息处理活动并对数据进行处置；
3. 法律法规有要求或合同有约定的，按照法律法规和合同执行。

### 申诉、投诉和咨询

网络运营者应提供机构和个人的申诉、投诉和咨询的方法和途径，并对其进行管理，具体要求如下：

1. 申投诉渠道为即时响应方式（例如电话、即时通信工具等）的，应在用户尝试三次内，单次等待时间不超过3分钟，可接通，申投诉渠道为非即时响应方式（例如邮件、网站留言等）的，应在收到申投诉后3个工作日内进行响应，申投诉应可以进行升级；
2. 接到有关发布损害他人合法权益信息的举报投诉时，接到相关假冒、仿冒、盗用他人名义发布信息的举报投诉时，应立即响应，进行核实，并在核实后停止传播并删除发布的信息；
3. 接到关于自动决策相关的申诉时，应在3个工作日内，或在决策生效前进行响应，进行人工复核，并在决策生效前进行处理；
4. 对申投诉进行处理，并记录处理过程，且满意度应达到90%以上。

## 履行对用户行为管理的义务

网络运营者应对其提供的即时通讯社交平台中用户的操作行为进行管理，督促用户对其个人行为负责，具体要求如下：

1. 应要求用户提供证实身份的材料，为用户建立不可更改的用户标识，用户标识可追溯到个人；
2. 在其进行操作前应对用户的身份进行核实；
3. 应建立用户行为准则，并逐一送达用户；
4. 应对用户的行为进行监控，发现违反行为准则的情况，进行及时进行阻止，当用户行为对国家安全、经济运行、社会稳定或他人的合法权益造成损害的，应立即阻止其行为，并实施措施降低影响。

# 数据共享、转让、发布和委托处理管理与安全控制

## 数据共享、转让、发布和委托处理管理

网络运营者应对数据共享、转让、发布和委托处理活动的合规性和风险进行管理，具体要求包括：

1. 仅按照数据保护清单列明的数据及数量，实施规定范围内的数据共享、转让、发布和委托处理；
2. 对数据共享、转让、发布和委托处理活动可能造成的影响应进行分析，实施风险评估，经评估可能危害国家安全、公共安全、经济安全、社会稳定，损害他人合法权益的，不得进行共享、转让、发布和委托处理，对于可以进行共享、转让、发布和委托处理的，应根据风险评估结果采取相关措施；
3. 个人信息的共享、转让、发布和委托处理不应超出个人信息主体授权的范围，其他数据主体控制者的数据使用应确保在与数据控制者达成协议范围内，如果超出范围应在共享、转让、发布和委托处理前重新获得授权；
4. 对网络运营者兼并、重组和破产发生的数据转让时，网络运营者应对数据接收方的数据安全保障能力进行评审，确保数据接收方有能力承担并承担了数据安全责任和义务，没有数据接收方时，应删除数据；
5. 数据提供方和接收方均在境内时，数据传输不应路由到境外，数据接收方在境外时，应满足本标准13章对数据出境管理与安全控制要求；
6. 应规定数据共享、转让、发布和委托处理的过程中的数据交付、数据接收、数据传输等重要操作的规程，并记录操作信息；对数据共享、转让、发布和委托处理的重要操作过程监控，如发现存在问题，及时采出措施进行改进；
7. 不得发布个人生物识别信息和基因、疾病等个人生理信息；
8. 网络运营者分析利用所掌握的数据资源，发布市场预测、统计信息、个人和企业信用等信息前应进行安全影响分析，并满足b）的要求。

## 对数据共享、转让和委托处理的数据接收方和受委托方管理

网络运营者应对数据的共享、转让和委托处理的数据接收方和受委托方的数据安全保护能力进行管理，确保共享、转让和委托处理时的数据安全，具体要求如下：

1. 应明确数据接收方和受委托方的数据安全保护能力要求，以及履行的法律责任和合同的义务；
2. 与数据接收方和受委托方签订合同或协议，合同或协议应至少包括：
3. 共享、转让和委托处理的数据范围（包括内容和数量）、方式和目的；
4. 适用时，共享与转让数据的可使用范围；
5. 适用时，委托的数据活动，特别，如果网络运营者运营的数据相关的业务需要国家或行业许可，应核查受委托方的许可证书，确保受委托方也获得了同样的许可；
6. 双方对共享、转让和委托处理的数据的安全保护责任和义务，特别，应明确诸如保密期限等时效的特殊要求；
7. 出现数据安全事件及意外情况的通知和处理要求，数据安全事件的处理应至少满足本标准对数据安全事件与应急的管理要求；
8. 数据共享、转让和委托处理中止和终止的条件，并明确合同中止和终止前后对数据安全的特殊要求，至少包括数据的保存和处理要求，数据的使用要求。
9. 在签订数据的共享、转让和委托处理合同或协议前，应对数据接收方和受委托方的数据安全保护能力进行评价，以确认其有能力承担的合同或协议的责任和履行其应尽义务；
10. 合同或协议执行期间，应通过实时监测、定期或不定期检查、要求定期报告、收集投诉等方式，对共享、转让的数据接收方的数据使用和受委托方的数据活动进行监视，以确认数据接收方能够有能力持续承担的合同或协议的责任和履行其应尽义务。如发现问题，及时采取措施进行改进，采取的措施可以包括立即改正或停止数据共享、转让和委托。

# 数据出境管理与安全控制

## 数据出境管理

网络运营者在开展数据活动过程中，需要向境外提供在中华人民共和国境内运营中收集和产生的个人信息和重要数据时，应实施数据出境管理，以确保出境数据的合法性，采取相关措施，保证数据安全，具体要求如下：

1. 仅按照数据保护清单列明的数据及数量，用确定的方式在规定范围内实施数据出境；
2. 境内用户访问境内互联网的，其流量应不被路由到境外
3. 向境外提供个人信息前，应委托具有个人信息出境评估资格的服务机构进行个人信息出境安全评估；
4. 向境外提供重要数据前，应委托由国家网信部门会同国家市场监管部门认定的服务机构进行重要数据出境安全评估；
5. 向境外提供重要数据之前，应按要求形成专门的材料报告行业监管部门，无行业监管部门的报省级网信部门，且得到批准。

## 数据出境安全控制

网络运营者在实施数据出境活动时，应进行影响分析和风险评估，并采取相关措施，保证数据安全，具体要求如下：

1. 向境外提供个人信息和重要数据时，应通过加密等方式确保传输过程的安全，防止跨境数据传输泄露、丢失、被篡改和非法使用；
2. 当跨境数据出现数据安全事件、发现境外数据接收方出现未履行其责任和义务、超范围使用、安全保护能力不足时，立即停止数据出境，并采取措施消除影响。

## 对数据出境数据接收方管理

网络运营者在实施数据出境活动时，应对境外的数据接收方的安全保证能力进行管理，以保证数据合规使用和数据安全，具体要求如下：

1. 应明确数据接收方的数据安全保护能力要求，以满足本标准的要求，以及履行的法律责任和合同的义务；
2. 与数据接收方签订合同或协议，合同或协议应至少包括：
3. 数据出境的目的、数据范围（包括内容和数量）、可使用范围和方式；
4. 双方对出境数据的安全保护责任和义务，特别，应明确诸如保密期限等时效的特殊要求；
5. 出现数据安全事件及意外情况的通知和处理要求，数据出境的中止和终止条件，并明确合同中止和终止前后对数据安全的特殊要求，至少包括数据的保存和处置要求，以及数据的使用要求，确保出境的数据受控。
6. 在签订数据出境合同或协议前，应对数据接收方的数据安全保护能力进行评价，以确认其有能力承担的合同或协议的责任和履行其应尽义务；
7. 合同或协议执行期间，应通过实时监测、定期或不定期检查、要求定期报告、收集投诉等方式，对出境的数据接收方的数据使用和委托处理的数据接收方的数据活动进行监视，以确认数据接收方能够有能力持续承担的合同或协议的责任和履行其应尽义务。如发现问题，及时采取措施进行改进，采取的措施可以包括立即改正或停止数据出境。

# 第三方应用接入管理与安全控制

当网络运营者在其产品或服务中接入具备个人信息和重要数据处理功能的第三方产品或服务时，应对第三方的接入和涉及的产品和服务进行管理，确保不因第三方的应用接入而危害数据安全，具体要求如下：

1. 应对第三方产品或服务的接入进行安全影响分析和风险评估，根据安全影响分析的结果确定是否接入该产品或服务，对于确定接入的产品或服务，应根据风险评估的结果实施适当的控制措施；
2. 应明确标识第三方产品或服务是否满足本标准的要求，包括满足、不满足或未评价三种状态标识；
3. 应与第三方产品或服务提供方签订合同或协议，约定双方的数据安全责任和义务，明确数据接收方的数据安全保护能力要求，以及履行的法律责任和合同的义务；
4. 应对第三方嵌入或接入的自动化工具（如代码、脚本、接口、算法模型、软件开发工具包、小程序等）的功能和安全性进行验证确认，如果第三方产品和服务发生变更，应重新进行验证确认；
5. 应对第三方接入产品和服务的数据处理活动进行必要的监视，并保留记录，确保其满足合同或协议要求，发现第三方产品或服务没有落实安全管理要求和责任的，及时督促其整改，必要时停止接入；
6. 向用户直接提供服务的第三方产品或服务接入后应在用户界面清晰标识产品或服务的提供方；
7. 网络运营者与第三方产品或服务之间的数据共享应满足本标准第10章的要求。

# 组织和人员保障

## 数据安全保护组织

网络运营者应确定承担数据安全保护职责的所有相关部门，并将落实保护措施、履行管理职责分配到人。

数据安全保护的职责至少应包括：

1. 数据保护范围的确定；
2. 数据安全影响分析与风险评估；
3. 数据安全保护计划制定；
4. 数据安全事件与应急管理；
5. 数据安全审计；
6. 数据安全保护资源保障；
7. 数据安全培训的开展；
8. 数据活动的责任。

收集个人敏感信息和重要数据的网路运营者应建立专门的数据安全保护委员会实施数据安全管理，监督数据安全保护的实施进程，及时解决实施过程出现的问题，从而保障数据安全目标得到实现。

## 数据安全责任人

网络运营者的主要责任人确定数据安全责任人，并通过正式的授权明确其责任和权力，数据安全责任人应由网络运营者的管理层人员承担。

### 能力要求

数据安全责任人应具备相关领域的工作经历，具有数据安全相关专业知识。相关领域的工作经历包括但不限于数据治理、IT治理、信息安全管理等，相关专业知识包括但不限于数据分析、网络安全、数据安全等。

网络运营者应定期（最长不超过十二个月）或在数据安全责任人进行变更时，对数据安全责任人的能力进行评价，并根据评价结果采取培训、调岗或重新招聘等需要的措施。

### 职责

据安全责任人对数据安全负直接责任，能够独立履职，不受外部干扰，特别不因履职而受到辞退、调离、换岗等处理，其应履行如下职责：

1. 参与有关数据活动的重要决策，直接向网络运营者的主要负责人报告工作；
2. 确定数据安全保护范围，组织制定数据安全保护目标和计划；
3. 确保开展数据安全风险评估，督促落实风险处置计划，确保测量风险控制措施的有效性；
4. 定期（最长不超过12个月），组织向社会发布安全风险评估报告；
5. 组织制定、签发、实施、更新隐私政策；
6. 组织制定数据安全管理程序并监督实施，进行绩效评价，确保持续改进；
7. 按要求向有关部门和网信部门报告数据安全保护和事件处置情况，公布投诉、举报方式等信息，及时组织受理并处理用户投诉和举报。

## 人力资源

网络运营者应确保有充分的人力资源能够落实保护措施、履行管理职责，具体活动包括：

1. 确定所有与数据安全保护相关的岗位及其责任和能力要求，并定期（至少一年）或岗位发生变化时对其进行评审；
2. 定期（至少一年）分析和确定这些岗位目前和未来（至少一年）的人员数量需求；
3. 对现有岗位人员进行能力评价，并定期（至少两年）对人员能力进行再评价，确定人员能力和数量是否满足要求；
4. 对于不满足的情况，采取适当措施，满足人员能力和数量要求；
5. 通过考试、测试、评价等方式对采取的措施的有效性进行评价；
6. 保留上述活动形成的文件，至少包括：
   1. 岗位职责能力文件和文件评审记录
   2. 人员数量分析文件；
   3. 能力评价记录；
   4. 培训计划、培训记录、调岗和招聘记录；
   5. 考试、测试和评价等活动的记录。

注：适用的措施可包括，例如针对现有雇员提供培训、指导或重新分配；雇佣或签约有能力的人员。

## 意识教育与培训

网络运营者应采取措施不断提升数据安全管理相关人员的能力和安全意识，包括：

1. 制定年度培训计划（培训计划的内容），并按计划实施培训，保留培训记录；
2. 培训计划至少包括以下方面的培训：
   1. 人力资源管理中识别的能力提升培训；
   2. 数据安全意识培训；
   3. 数据安全管理知识培训；
   4. 数据安全管理技术培训；
   5. 数据安全管理制度要求培训；
   6. 需要时，进行新技术的培训。

# 事件与应急管理

## 事件管理

网络运营者通过对超范围采集、泄露、窃取、篡改、毁损、不正当使用等数据安全事件进行管理，确保数据安全事件在发生时得到及时发现和解决，具体包括：

1. 应制定事件处理流程，明确事件的分类、分级原则，明确事件的报告、记录、影响评估、确定类别和级别等活动以及按不同分类的解决过程、关闭和沟通机制，确保流程得到执行，并保留相关证据；
2. 应采取手段发现对数据安全产生影响的事件，包括：
   1. 对数据活动涉及的信息系统、网络系统和各类应用的操作进行监控，并形成日志，定期对日志进行审计；
   2. 对数据活动涉及的信息系统、网络系统和各类应用的运行进行监控，通过告警的方式对出现的事件进行提示；
   3. 对数据活动的执行情况定期进行审计；
   4. 接受主管部门告知、外部投诉和举报等其他手段。
3. 发生个人信息泄露、毁损、丢失等数据安全事件时，网络运营者应及时以公告、电话、短信、邮件或信函等方式告知个人信息主体，并向行业主管监管部门和网信部门报告；
4. 事件如果无法在规定时间内处理完成，或者事件造成的影响扩大，应立即对事件进行升级处理；
5. 事件的影响范围超过100万人，或影响到国家安全、公共安全时，应启动应急预案。

## 事件应急管理

网络运营者应建立数据安全事件应急管理制度，确保数据安全事件在发生时得到及时控制，具体包括：

1. 根据数据安全影响分析、合规性要求分析和风险评估的结果，确定需要制定应急预案的事件清单，事件清单应至少包括影响范围超过100万人，或影响到国家安全、公共安全的事件；
2. 针对这些事件建立应急预案，应急预案的内容至少应包括：
   1. 启动应急预案的责任人；
   2. 应急预案启动后要实现的目标及启动的条件；
   3. 应急预案启动所需的资源；
   4. 事件的应急处理活动、可能出现的操作及活动与操作的人员安排，编制相关操作手册及其索引；
   5. 应急沟通方式和相关人员的联系方式；需要对外发布事件信息时，需要明确发布条件、方式和发言人；
   6. 应急执行结束后的恢复建议。
3. 配备应急预案所需的资源，包括人、设备、场所、工具、资金、文件等；
4. 制定应急预案演练计划，按计划或在应急预案发生变化后，进行应急预案的测试和演练，对演练过程进行记录，事后进行分析，必要时，依据分析的结果对应急预案实施改进，计划至少应包括：
   1. 应急预案演练的周期、具体演练的时间、方式等安排，明确演练的责任人、参与人及资源需求等；
   2. 应急演练事件选择和场景设计，演练过程责任人和参与人的具体操作要求；
   3. 演练过程的记录、总结要求。
5. 应急预案执行结束后应进行总结分析，形成应急预案执行分析报告，必要时，依据分析的结果对应急预案实施改进；
6. 应明确数据安全事件应急管理目标和评价要求；
7. 应明确数据安全事件应急管理记录保持要求。

# 符合性管理和持续改进

## 法律法规和合同符合性管理

网络运营者应识别与数据安全相关的所有法律法规要求和合同义务，形成清单，并对其进行管理，包括：

1. 编制法律法规要求和合同义务清单，内容应包括：
   1. 法律法规以及合同名称和生效日期；
   2. 法律法规的发布方和合同的约定方；
   3. 法律法规和合同中与数据安全相关的条款；
   4. 网络运营者满足法律法规要求和合同义务的方式和证据。
2. 评审法律法规清单中明确的法律法规要求和合同义务是否充分和适宜；
3. 定期（最长不超过12个月）对清单进行更新和评审，当法律法规和合同发生变化时，及时对清单进行更新和评审。

## 标准符合性管理

网络运营者应通过保护措施有效性、保护目标的实现程度、数据安全管理过程有效性的评价，实现对标准符合性的管理，具体要求包括：

1. 针对数据安全保护计划明确采取的措施，按照数据安全保护计划的安排实施评审，对发现的问题及时进行改进；
2. 定期（最长不超过12个月）或当组织结构、主要负责人、数据活动、法律法规和合同要求发生重大变化时，对数据安全保护目标的实现程度进行评审，发现存在差距的及时采取措施进行改进；
3. 定期（最长不超过12个月）或当组织结构、主要负责人、数据活动、法律法规和合同要求发生重大变化时，对数据安全保护范围、隐私政策、数据安全保护计划、组织与人员保障、事件与应急管理等管理过程的适应性和充分性，以及实施的有效性进行评审，形成评审报告，对评审发现的问题及时采取措施进行改进；
4. 必要时，聘请公正第三方机构进行独立评审，对独立评审发现的问题，及时采取措施进行改进。

影响分析与风险评估参考模型

C.1. 数据安全影响分析

网络运营者应对列入保护范围的数据发生泄露、毁损、丢失等事件时，对国家安全、经济安全、社会稳定、公共健康和安全以及数据主体（个人信息主体）合法权益可能造成的影响进行分析，建立安全影响判定准则，并依据准则确定列入数据保护范围的数据的安全影响级别。安全影响分析应定期进行，最长不超过12个月。如列入数据保护范围内的数据及数据活动发生重大变化时，应及时开展数据安全影响分析。

C.2. 数据安全风险分析

网络运营者应根据数据安全影响分析结果，对造成影响的事件发生的可能性进行分析，具体包括：

1. 识别数据运营过程中和数据流转过程中可能造成数据安全影响的事件，至少包括数据超范围采集、泄露、窃取、篡改、毁损、不正当使用等方面的事件；
2. 识别引起事件发生的可能原因；
3. 制定事件发生可能性判定准则，确定事件发生的可能性；
4. 根据数据安全事件发生的可能性及影响计算风险值，形成数据安全风险清单。

C.3. 数据安全风险评价

网络运营者应制定风险评价准则，依据准则对数据安全风险清单中的风险进行评价，确定风险等级，形成风险评估报告。
