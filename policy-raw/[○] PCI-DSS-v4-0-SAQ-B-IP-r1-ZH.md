商户自我评估调查问卷 B-IP 资格标准

自我评估调查问卷（SAQ）B-IP 仅包括适用于仅通过独立的、列于 PCI 的经认证 PIN 交易安全（PTS）交互点（POI）[[1]](#footnote-2)设备处理账户数据并 IP 连接到支付处理商的商户的 PCI DSS 要求。

例外情况适用于被归类为安全读卡器（SCR）和密码安全读卡器（SCRP）的 PTS POI 设备；使用 SCR 或 SCRP 的商户不合资格填写本 SAQ。

SAQ B-IP 商户可以是实体店（实体信用卡）或邮购/电话订购（虚拟信用卡）商户，并且不在任何计算机系统上存储帐户数据。

***本 SAQ 不适用于电子商务渠道。***

***本 SAQ 不适用于服务提供者。***

SAQ B-IP 商户确认，对于这种支付渠道:

* 商户仅使用独立的、列于 PCI 的经认证1PTS POI 设备（不包括 SCR 和 SCRP），通过 IP 连接到商户的支付处理商，以获取客户的支付卡信息；
* 根据列于 PCI SSC 网站上的 PTS POI 计划（不包括 SCR 和 SCRP）认证与 IP 连接的 独立 POI 设备；
* 与 IP 连接的独立 PTS POI 设备不与商家环境中的任何其他系统连接（这可以通过网络分段实现，将 PTS POI 设备与其他系统隔离开来)[[2]](#footnote-3)；
* 帐户数据的唯一传输是由经批准的 PTS POI 设备传输到支付处理商；
* PTS POI 设备不依赖任何其他设备（例如电脑、手机、平板电脑等）来连接到支付处理商；
* 商户不以电子格式存储帐户数据；以及
* 商户以纸质形式保留任何帐户数据（例如，打印的报告或收据），而这些文件不是以电子方式接收的。

本 SAQ 仅包括那些适用于特定商户环境类型的要求，如上述资格标准中所定义的那样。如果本 SAQ 没有涵盖任何适用于持卡人数据环境的 PCI DSS 要求，这可能表明本 SAQ 不适合商户的环境。

## 确定帐户数据、持卡人数据和敏感验证数据

PCI DSS 适用于所有存储、处理或传输持卡人数据（CHD）和/或敏感验证数据（SAD）或可能影响持卡人数据环境（CDE）安全性的实体。持卡人数据和敏感验证数据被视为帐户数据，确定方式如下：

| 帐户数据 | |
| --- | --- |
| 持卡人数据包括： | 敏感验证数据包括： |
| * 主帐户号（PAN） * 持卡人姓名 * 到期日 * 业务码 | * 全磁道数据（磁条数据或芯片上的同等数据） * 卡验证代码 * PIN/PIN 数据块 |

欲了解更多详情，请参阅 PCI DSS 第 2 部分，PCI DSS 适用性信息。

## PCI DSS 自我评估完成步骤

1. 通过审核本 SAQ 和 PCI SSC 网站上的*自我评估调查问卷说明和指南*文件中的资格标准，确认这是适合商户环境的正确 SAQ。
2. 确认商户环境是否正确界定。
3. 评估环境是否符合 PCI DSS 要求。
4. 完成本文件的所有部分：

* 部分 1：评估信息（遵从性证明书（AOC）的第 1 和第 2 部分–联系信息和执行摘要）。
* 部分 2：自我评估调查问卷 B-IP。
* 部分 3：认证和证明的细节（AOC 的第 3 和第 4 部分 - PCI DSS 不符合要求的认证和行动计划（如果第 4 部分适用））。

1. 提交 SAQ 和 AOC 以及任何其他要求的文件（例如 ASV 扫描报告）给要求的组织（管理遵从性计划的组织，例如支付品牌和收单机构）。

## 预期测试

载于“预期测试”一栏中的说明是基于 PCI DSS 中的测试程序，并具体描述了商户预期执行以核实某项要求是否得到满足的测试活动类型。

每个测试方法的目的描述如下：

* + - 检查：实体严格评估数据证据。常见示例包括文件（电子或物理）、屏幕截图、配置文件、检查日志和数据文件。
    - 观察：商户观察其环境中的某些事物或动作。观察对象的示例包括执行任务或流程的人员、执行功能或响应输入的系统、环境条件和物理限制。
    - 询问：商户与个别工作人员进行交谈。询问的目的可能包括确认是否执行了某项活动，描述如何执行某项活动，以及相关人员是否具有特定的知识或理解。

测试方法旨在让商户证明他们满足要求的具体方式。要检查或观察的特定项目和要询问的人员应该适合于被评估的要求和商户的特定实施。

可在 PCI DSS 中查询每项要求的测试程序的完整细节。

## 要求答复

对于每项要求项目，可以选择一个答复来表明商户在该要求方面的状态。***每项要求项目只应选择一个答复。***

下表解释了关于每个答复的含义以及使用每个答复的具体时间。

| 答复 | 什么时候使用这一答复： |
| --- | --- |
| **已到位** | 已经执行了预期测试，并已按规定满足了要求的所有元素。 |
| **已到位并填写了 CCW**  （补偿性控制工作表） | 已经执行了预期测试，在补偿性控制的协助下满足了要求。  本栏中的所有答复都需要填写本 SAQ 附录 B 中的补偿性控制工作表（CCW）。  PCI DSS 中的附录 B 和 C 提供了关于使用补偿性控制的信息以及关于如何填写工作表的指南。 |
| **不适用** | 该要求不适用于该商户的环境。(示例详见下文“不适用要求的指南”。)这一栏中的所有答复都需要在本 SAQ 中的附录 C 作出支持性解释。 |
| **未测试** | *该答复不适用于本 SAQ，也未被列为选项。*  *本 SAQ 是根据商户存储、处理和/或传输帐户数据的方式为特定类型的环境创建，并定义了适用于该环境的特定 PCI DSS 要求。因此，必须测试本 SAQ 中的所有要求。* |
| **未到位** | 要求中的一些或所有要素未得到满足，或正在实施中，或需要进一步测试，然后商户才能确认它们已到位。本栏的答复可能需要填写第 4 部分（如果提交本 SAQ 的实体要求）。  如因法律限制而无法满足要求，也会使用该答复。(更多指南见以下的“法律例外情况”）。 |

不适用要求的指南

如果有任何要求不适用于商户的环境，请为该特定要求选择“不适用”选项。例如，在本 SAQ 中，关于保护所有含有持卡人数据的媒体的要求（要求 9.4.1 - 9.4.6）仅在商户存储含有持卡人数据的纸质媒体的情况下适用；如果不存储纸质媒体，商户可以为这些要求选择“不适用”。

对于在本 SAQ 中选择“不适用”的每项答复，请填写*附录 C：要求标记为“不适用”的解释。*

关于答复未来日期要求的指南

*在下面的第 2 部分中，每项新的 PCI DSS 4.0版要求或具有延长实施期的项目符号都包括以下说明：*“*此要求[或项目符号]在 2025 年 3 月 31 日之前是最佳实践，在此日期后被要求实施并且必须在 PCI DSS 评估中予以充分考虑。"*

在未来日期过去之前，这些新要求不需要包含在 PCI DSS 评估中。在该未来日期之前，商户尚未实施的任何具有延长实施日期的新要求可被标记为不适用，并记录在附录C中：要求标记为“不适用”的解释。

法律例外情况

如果您所在组织受到无法使其满足 PCI DSS 要求的法律限制，请为该要求选择“未到位”，并完成本 SAQ 第 3 部分的第 3 节中的相关证明。

**注：**法律限制是指满足 PCI DSS 要求会违反当地或地区的法律或法规。

合同义务或法律建议不是法律限制。

| *SAQ 不支持使用定制的方法。* |

SAQ 不能用于记录使用定制的方法来满足 PCI DSS 要求。由于这个原因，定制的方法的目标不包括在 SAQ 中。希望使用定制的方法进行认证的实体可以使用 PCI DSS 遵从性报告（ROC）模板来记录其评估结果。
