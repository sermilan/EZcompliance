# COU-R-20274-3-8-7-6-0

> **来源**: [[GBT 20274.4-2008]]
> **章节**: 第3级 - PEN_MSP.5 评审安全态势 - 8.7.6(8.7.6)
> **层级**: R (原始COU · Raw)
> **基础权重**: 9.6

## 解剖结构

| 要素 | 内容 |
|------|------|
| 主体 | 网络安全等级保护对象运营者 |
| 动作 | 定期 |
| 客体 | 检查。实际上,开发环境也可以看作是系统开发的运行环境 |
| 条件 | 定级为第3级时 |
| 权重计算 | 9.6 × 1.3 = **12.5** |

## 原文

> 应根据当前运行环境和发生的变更检查安全态势。如果其他事件(例如变更)没有触发安全整体检查,应该根据上次检查的时间间隔来触发检查。时间触发的检查应符合策略和规则。检查应重新评估当前安全的充分性以及当前风险接受级别的恰当性。检查应根据组织的安全评估方法,参见 PRM_ASR 评估安全风险。与检查运行环境一样的方式,系统创建所处的开发环境也应定期检查。实际上,开发环境也可以看作是系统开发的运行环境。
